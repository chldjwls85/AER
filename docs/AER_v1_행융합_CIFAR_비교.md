# AER v1 행 융합 CIFAR10-DVS 비교

## 1. 구현한 내용

기존 행 머리말에는 뱅크 주소, 행 주소, 유효 타일 열 비트맵이 이미 들어 있다. 외부 링크 수신 시각을 쓰는 조건에서는 타일별 시간차가 필요하지 않으므로, 선택된 행의 모든 유효 타일이 같은 압축 형식일 때 데이터를 한 워드로 합쳤다.

```text
동종 BIN4 행:   HEADER → ROW_BIN4
동종 GROUP3 행: HEADER → ROW_GROUP3
혼합 행:        HEADER → 기존 타일별 DATA
```

뱅크·행 선택 순서와 순환 중재기는 변경하지 않았다. 압축을 위해 기다리지 않으며, 선택된 행을 즉시 검사해 융합하거나 기존 형식으로 전송한다.

행 융합은 `EXTERNAL_RX_TIMESTAMP=1`일 때만 허용한다. 수신 시각은 기존 방식과 동일하게 헤더 첫 워드가 외부 링크에 도착한 클록이다. 따라서 행 융합 때문에 새로운 대표 시각을 계산하거나 타일별 시각을 추가로 섞지 않는다.

## 2. 비교 조건

- 입력: CIFAR10-DVS `airplane_0` 전체 178,165이벤트
- 부하: 1ms 이동 구간 최대 1GEPS가 되도록 1297.016861배 재생
- 센서: 128×128픽셀
- 픽셀 입력 저장: 모든 구조에서 픽셀당 2-entry
- 공통 구조: 2×2 타일, 4×4타일 뱅크, 같은 순환 중재기·계층 버퍼·16비트 단일 링크
- 시간: 외부 링크의 패킷 첫 워드 수신 시각
- 비교: 행 융합, 기존 BIN4/GROUP3 비닝, 무비닝 RAW8
- 도구: 로컬 Vivado 2024.1 XSim 기능 시뮬레이션
- 합성: 수행하지 않음

같은 주파수의 세 구조는 같은 입력 벡터를 사용했다. SHA-256은 100MHz에서 `83a1815f...d759`, 200MHz에서 `8e14c6e...1376`으로 각각 일치한다. 모든 행 융합 패킷은 소프트웨어 복호 후 수락 타일과 위치·극성이 일치했으며 무결성 오류는 0건이다.

## 4. 행 융합 발생량

| 주파수 | ROW_BIN4 워드 | ROW_GROUP3 워드 | 융합 타일 | 같은 입력을 기존 형식으로 보낼 때보다 절약한 DATA 워드 |
|---|---:|---:|---:|---:|
| 100MHz | 617 | 178 | 2,494 | 635 |
| 200MHz | 195 | 205 | 974 | 241 |

`절약한 DATA 워드`는 동일하게 수락된 행을 기존 BIN4 두 개 패킹 또는 GROUP3 개별 전송으로 보냈다고 가정한 국소 비교다. 전체 출력 워드 감소가 635·241보다 작은 이유는 확보된 링크 여유로 더 많은 이벤트를 받아 타일 그룹과 행 머리말도 추가 전송했기 때문이다.

## 5. 해석

행 융합 회로는 의도대로 동작했지만 이 CIFAR 구간에서는 기존 비닝보다 개선 폭이 작다. 주된 이유는 다음과 같다.

1. 행 융합은 한 뱅크 행의 유효 타일이 모두 같은 BIN4 또는 GROUP3일 때만 가능하다.
2. 100MHz에서 융합된 타일은 전체 수신 타일 그룹의 약 3.38%, 200MHz에서는 약 0.86%다.
3. 200MHz에서는 이벤트가 더 빨리 빠져 한 행에 동종 압축 타일이 동시에 모일 가능성이 줄었다.
4. 행마다 머리말 한 워드는 그대로 필요해 DATA 절약이 전체 링크 워드에 미치는 영향이 제한된다.

따라서 행 융합은 안전한 추가 최적화로는 유효하지만, 현재 결과만으로 핵심 기여로 올리기는 어렵다. 다음 후보는 중재 우선순위를 바꾸거나 기다림을 추가하는 방식이 아니라, 혼합 행에서도 16비트 안에 여러 짧은 토큰을 연속 배치하는 일반 패커다. 이 경우에도 같은 입력·중재·버퍼·링크 조건으로 기존 세 구조와 비교해야 한다.
