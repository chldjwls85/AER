# 손실형 2×2 비닝 Python 재검증

## 1. 결론

기존 Python 구조 모델은 손실형 비닝의 패킷 형식은 올바르게 모델링했지만, 실제 RTL의 입력 비트맵과 클록 단위 역압을 충분히 반영하지 못했다. 따라서 기존에 보고한 `200MHz 전체 오류율 상대 감소 41.74%`는 RTL 성능 예측값으로 사용할 수 없다.

이를 수정하기 위해 `sw/rtl_cycle_model.py`를 추가했다. 새 모델은 현재 Verilog RTL과 동일하게 다음 항목을 처리한다.

- 픽셀별 ON/OFF 1비트 입력
- 같은 픽셀·같은 극성·같은 클록의 중복 이벤트 합침
- 픽셀당 깊이 2 FIFO와 동시 입력·팝
- 2×2픽셀 타일과 타일별 뱅크 대기 슬롯
- 4×4타일 뱅크의 행 중재와 패킷 잠금
- 256개 뱅크를 연결하는 2단 선택기
- 선택기 단계별 깊이 2 FIFO와 `valid/ready` 역압
- 16비트 출력 링크에서 클록당 최대 1워드

CIFAR10-DVS 전체 입력을 다시 실행한 결과, Python 모델은 XSim과 수용 이벤트, 무시 이벤트, 동일 클록 중복, 타일 그룹, 출력 워드, 가짜 이벤트를 모두 정확히 재현했다.

## 2. 기존 모델에서 잘못 단순화한 부분

기존 `sw/lossy_binning_model.py`는 구조 탐색과 패킷 형식 검증을 위해 작성했다. 이 모델에서는 소스 이벤트를 픽셀별 Python `deque`에 하나씩 넣었기 때문에 같은 클록에 같은 픽셀로 들어온 이벤트도 FIFO 여유가 있으면 각각 저장할 수 있었다.

실제 RTL 입력은 픽셀마다 ON 1비트와 OFF 1비트다. 같은 클록에 동일한 픽셀·극성 이벤트가 여러 번 발생하면 한 번의 요청으로만 표현된다. 또한 기존 모델은 뱅크 패킷의 워드 수만 이용해 링크 점유 시간을 계산했지만, RTL에는 다음 동작이 추가로 존재한다.

1. 픽셀 FIFO에서 타일 스냅숏을 만드는 시점
2. 타일별 뱅크 대기 슬롯이 빌 때까지의 역압
3. 뱅크 내부 행 단위 Round-robin 중재와 패킷 잠금
4. 두 단계 선택기와 각 단계의 깊이 2 FIFO

따라서 기존 41.74%는 손실형 인코딩의 가능성을 살펴본 추상 모델 결과로만 남기고, 전체 RTL 성능 수치에는 새 클록 정확도 모델과 XSim 결과를 사용한다.

## 3. 공통 검증 조건

| 항목 | 값 |
|---|---|
| 데이터 | CIFAR10-DVS `airplane/0`, 처음 178,165이벤트 |
| 센서 | 128×128 |
| 타일 | 2×2픽셀 |
| 뱅크 | 4×4타일, 즉 8×8픽셀 |
| 선택기 | 4×4 입력 단위 2단 계층 |
| 픽셀 FIFO | 픽셀당 깊이 2 |
| 출력 | 16비트, 클록당 최대 1워드, 항상 수신 가능 |
| 재생 속도 | 1297.016861배, 약 1GEPS 부하 |
| 클록 | 100MHz, 200MHz |
| 오류 정의 | 전송 전 손실 + 3→4 복원으로 추가된 가짜 이벤트 |

`RAW`와 손실형 구조는 입력, FIFO, 뱅크, 선택기, 링크 조건을 공유한다. 차이는 손실형 구조가 비용 이득이 있을 때만 `3-of-4/4-of-4 공통 BIN`과 혼합 뱅크 패킹을 사용한다는 점이다.

## 4. Python과 XSim 일치 결과

### 100MHz

| 지표 | RAW Python/XSim | 손실형 Python/XSim |
|---|---:|---:|
| 원본 이벤트 | 178,165 | 178,165 |
| 받아들인 이벤트 | 140,110 | 156,096 |
| FIFO에서 무시 | 33,834 | 17,848 |
| 동일 클록 중복 | 4,221 | 4,221 |
| 전체 전송 전 손실 | 38,055 | 22,069 |
| 의도적 가짜 이벤트 | 0 | 3,692 |
| 전체 오류율 | 21.3594% | 14.4591% |
| 출력 워드 | 103,071 | 100,129 |

손실형 구조의 전체 오류율은 RAW보다 `6.9003%p`, 상대적으로 `32.3059%` 감소했다.

### 200MHz

| 지표 | RAW Python/XSim | 손실형 Python/XSim |
|---|---:|---:|
| 원본 이벤트 | 178,165 | 178,165 |
| 받아들인 이벤트 | 160,063 | 166,790 |
| FIFO에서 무시 | 14,229 | 7,502 |
| 동일 클록 중복 | 3,873 | 3,873 |
| 전체 전송 전 손실 | 18,102 | 11,375 |
| 의도적 가짜 이벤트 | 0 | 1,940 |
| 전체 오류율 | 10.1602% | 7.4734% |
| 출력 워드 | 178,503 | 162,834 |

손실형 구조의 전체 오류율은 RAW보다 `2.6868%p`, 상대적으로 `26.4446%` 감소했다. 출력 워드는 `8.7780%` 줄었다.

## 5. 해석

새 결과에서도 손실형 비닝의 핵심 가설은 성립한다. 200MHz에서 3→4 복원으로 1,940개의 가짜 이벤트가 추가됐지만, 혼잡으로 사라지는 실제 이벤트는 6,727개 줄었다. 따라서 전체 오류는 4,787개 감소했다.

다만 성능 개선폭은 기존 추상 모델의 41.74%가 아니라, 현재 RTL 계층을 반영한 26.44%다. 앞으로 보고서와 자기소개서에서 RTL 구현 성능을 설명할 때는 이 값을 사용한다.

`sw/lossy_binning_model.py`는 다음 용도로만 유지한다.

- 타일 분류 규칙 확인
- 손실형 패킷 비트 배치의 독립 기준 모델
- 대표 뱅크 스냅숏의 Python·RTL 비트 단위 비교

전체 시스템의 손실률과 처리량 평가는 `sw/rtl_cycle_model.py`를 기준으로 한다.

## 6. 재현

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_lossy_binning_sw.ps1
```

- 클록 정확도 모델: `sw/rtl_cycle_model.py`
- 패킷 기준 모델: `sw/lossy_binning_model.py`
- 단위 시험: `tests_sw/test_rtl_cycle_model.py`, `tests_sw/test_lossy_binning_model.py`
- 기본 결과: `results/lossy_binning_rtl_cycle_model/summary.json`

전체 178,165이벤트를 Python에서 모든 RTL 제어 상태까지 따라가므로 실행 시간이 기존 추상 모델보다 길다.
