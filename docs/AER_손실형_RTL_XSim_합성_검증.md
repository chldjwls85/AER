# AER 손실형 비닝 RTL·XSim·합성 검증

## 1. 결론

Python에서 시험한 `3-of-4/4-of-4 공통 BIN + 혼합 뱅크 패킹 + 비용 기반 RAW 복귀` 정책을 Verilog RTL로 구현했다. 독립 Python 기준 모델과 RTL의 패킷 워드는 세 가지 대표 조건에서 비트 단위로 일치했고, CIFAR10-DVS 전체 재생에서도 패킷 무결성 오류가 발생하지 않았다.

의도적 복원 오차까지 포함한 전체 오류율은 100MHz 기능 모델에서 RAW 21.36%→손실형 14.46%, 200MHz에서 10.16%→7.47%로 감소했다. 다만 현재 패커는 한 클록의 조합 논리로 비용 계산과 가변 길이 패킹을 수행하므로 합성 면적과 임계 경로가 크다. 따라서 이번 결과는 기능과 전송 정책의 타당성을 검증한 것이며, 100MHz·200MHz에서 물리적으로 동작 가능한 최종 회로를 뜻하지 않는다.

## 2. 구현 내용

- 입력: 2×2픽셀의 ON 4비트, OFF 4비트
- 뱅크: 4×4타일, 즉 8×8픽셀
- `3-of-4`와 `4-of-4`: 같은 극성 1비트 BIN
- 그 밖의 조합: ON/OFF를 보존하는 RAW8
- 혼합 패킷: 유효 타일 비트맵, BIN 타일 비트맵, 가변 길이 데이터
- 선택 기준: 혼합 손실형 패킷이 RAW 뱅크와 행 RAW보다 모두 작을 때만 사용
- 동률 또는 이득 없음: 무손실 RAW 뱅크 또는 행 RAW로 복귀
- 타임스탬프: 패킷 첫 워드의 외부 링크 수신 클록

주요 RTL 매개변수는 `ENABLE_LOSSY_BINNING`이다. 제안 구조는 `ENABLE_BINNING=1`, `ENABLE_BANK_FUSION=1`, `ENABLE_LOSSY_BINNING=1`로 구성한다.

## 3. Python 기준 모델과 패킷 단위 일치

`sw.lossy_binning_model.encode_lossy_bank_snapshot()`과 `tb/v1/tb_aer_bank_lossy_mixed.v`에 같은 타일 스냅숏을 입력했다.

| 시험 | 선택 결과 | Python·RTL 공통 출력 워드 |
|---|---|---|
| RAW8 2개, GROUP3 3개, BIN4 3개 | 손실형 혼합 5워드 | `8177 00FF 007E 1910 0009` |
| GROUP3 1개, RAW8 1개 | 행 RAW 복귀 3워드 | `C143 0380 0040` |
| 네 행에 BIN 후보 1개씩 | 비용 동률, RAW 뱅크 복귀 4워드 | `8143 1111 F0F0 F0F0` |

세 경우 모두 워드 값, 순서, 마지막 워드 표시가 일치했다. Python 복호기 시험에서는 3-of-4 세 타일이 만든 가짜 픽셀 세 개를 의도적 오차로 분리 집계하고, 그 밖의 비트맵·패킷 오류는 0건임을 확인했다.

최종 자동 회귀에서는 Python·복호기 시험 26개와 XSim RTL 시험 14개가 모두 통과했다. XSim 묶음에는 기존 RAW8/GROUP3/BIN4, 행·뱅크 융합, 24×40 가변 크기, 적응형·RAW 128×128 전체 연결과 새 손실형 혼합 패킷 시험이 포함된다.

## 4. CIFAR10-DVS 전체 XSim 비교

### 공통 조건

| 항목 | 값 |
|---|---|
| 데이터 | CIFAR10-DVS `airplane/0`, 처음 178,165이벤트 |
| 센서/타일/뱅크 | 128×128 / 2×2픽셀 / 4×4타일 |
| 재생 배속 | 1297.016861배 |
| 목표 입력률 | 약 1GEPS |
| 픽셀 FIFO | 픽셀당 깊이 2 |
| 출력 | 16비트, 클록당 최대 1워드, `out_ready=1` |
| 시각 | 외부 링크의 패킷 첫 워드 수신 클록 |
| 오류 정의 | 전송 전 손실 + 3→4 복원으로 추가된 가짜 이벤트 |

### 100MHz 결과

손실형 구조는 전체 오류를 12,294개 줄였다. 오류율은 6.90%p, RAW 대비 상대적으로 32.31% 감소했다. 전송 전에 사라진 이벤트는 15,986개 줄었으며, 이 이득이 복원 과정에서 추가된 3,692개보다 컸다.

## 5. Python 클록 정확도 모델과 RTL 결과의 관계

기존 Python 구조 모델은 픽셀별 이벤트를 개별 큐에 넣고 링크 점유 시간을 패킷 워드 수로 단순화했다. 이 때문에 같은 클록의 중복 이벤트와 실제 선택기 FIFO의 역압을 RTL과 다르게 처리했고, 200MHz 상대 오류 감소를 41.74%로 과대평가했다.

이후 `sw/rtl_cycle_model.py`를 추가해 픽셀 ON/OFF 입력 비트맵, 깊이 2 FIFO, 타일·뱅크 수용 시점, 행 중재, 패킷 잠금, 2단 선택기 FIFO와 `valid/ready`를 RTL과 동일한 클록 순서로 모델링했다.

수정한 Python 모델은 CIFAR10-DVS 178,165이벤트의 100MHz·200MHz RAW/손실형 네 조건에서 다음 항목을 XSim과 모두 동일하게 재현했다.

- 받아들인 이벤트와 FIFO 무시 이벤트
- 같은 클록의 중복 이벤트
- 받아들인 타일 그룹
- 출력 워드
- 손실형 복원으로 추가된 가짜 이벤트

따라서 전체 성능 수치는 Python과 XSim에 공통으로 재현된 100MHz 상대 감소 32.31%, 200MHz 상대 감소 26.44%를 사용한다. 기존 추상 모델의 36.78%, 41.74%는 RTL 성능 근거에서 제외한다. 패킷 비트 배치는 기존 `sw/lossy_binning_model.py`를 독립 기준 모델로 계속 검증한다.

## 6. Vivado 합성 결과

Vivado 2024.1, `xc7z020clg484-1`, 5ns 제약에서 `aer_bank_row_reader` 한 개를 배치·배선 전 논리합성했다. 128×128 전체 회로가 아니라 손실형 패킹이 들어가는 한 뱅크의 비교다.

| 지표 | RAW 뱅크 | 손실형 뱅크 |
|---|---:|---:|
| LUT | 1,709 | 20,120 |
| FF | 327 | 593 |
| MUXF | 10 | 166 |
| 데이터 경로 지연 | 8.138ns | 27.103ns |
| 5ns 제약 최악 여유 | -3.145ns | -22.110ns |
| 지연 역수 참고값 | 약 122.9MHz | 약 36.9MHz |

두 구조 모두 200MHz 제약을 만족하지 못했다. 특히 손실형 뱅크는 유효 타일 16개의 형식에 따라 1비트와 8비트 데이터를 한 클록에 가변 위치로 패킹하는 조합 논리가 큰 다중 선택 회로로 합성됐다. LUT는 RAW보다 약 11.8배, FF는 81.3% 증가했다.

따라서 기능 시뮬레이션의 100MHz·200MHz 수치는 `그 속도로 한 워드/클록을 처리할 수 있다면`의 혼잡 비교다. 현재 RTL의 합성 후 달성 주파수로 해석하면 안 된다.

## 7. 다음 구현 방향

1. 16타일을 한 클록에 모두 패킹하지 않고 여러 클록에 나누는 순차 패커로 변경
2. 타일 분류·비용 계산·데이터 패킹 사이에 파이프라인 삽입
3. 패커 준비 중 새 이벤트를 받을 수 있도록 스냅숏 버퍼를 분리
4. 작은 8×8픽셀 한 뱅크에서 100MHz를 먼저 만족한 뒤 128×128 계층으로 확장
5. 배치·배선 후 타이밍과 전력을 다시 측정

## 8. 재현 명령

```powershell

powershell -ExecutionPolicy Bypass -File scripts/run_v1_xsim.ps1
```
