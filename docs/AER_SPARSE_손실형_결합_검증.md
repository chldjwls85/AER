# AER SPARSE·손실형 비닝 결합 검증

## 1. 결론

희소 구간에는 손실 없는 `SPARSE`, 혼잡 구간에는 기존 손실형 `BIN/RAW` 뱅크 패킷을 사용하는 결합 구조를 Verilog RTL과 Python 클록 모델에 함께 구현했다. 두 형식을 한 패킷에 억지로 섞지 않고, 현재 뱅크 상태에서 실제 전송 워드가 더 적은 경로를 선택한다.

이 구조는 CIFAR10-DVS 전체 기록을 1GEPS 입력 조건으로 재생한 Python 클록 모델에서 RAW 대비 전체 오류율을 100MHz에서 44.44%, 200MHz에서 48.52% 상대 감소시켰다. 다만 한 뱅크 논리합성에서는 SPARSE·뱅크·행 경로를 고르는 조합 경로가 길게 남아 200MHz 제약을 만족하지 못했다. 따라서 현재 결과는 전송 정책과 RTL 기능의 타당성을 보여 주지만, 목표 주파수를 만족한 최종 구현은 아니다.

## 2. 결합 원칙

### 희소 타일

2×2타일에서 ON 또는 OFF 이벤트가 정확히 하나면 위치와 극성을 다음 한 워드에 모두 보존한다.

```text
SPARSE = {0, bank_id[7:0], local_tile[3:0], pixel[1:0], polarity}
```

외부 링크 수신 시각 모드에서는 기존 행 RAW의 `HEADER+DATA` 두 워드가 한 워드로 줄어든다. 이벤트 위치를 버리지 않으므로 의도적 복원 오차는 없다.

### 혼잡한 뱅크

같은 극성 이벤트가 3개 또는 4개인 타일은 극성 1비트 BIN으로 표현하고, 그 밖의 타일은 RAW8로 보존한다. 손실형 패킷이 RAW 뱅크와 행 RAW보다 실제로 작을 때만 선택한다. 3개를 4개로 복원할 때 생기는 가짜 이벤트 하나는 전체 오류에 포함한다.

### 형식 선택

```text
혼잡 뱅크에서 손실형/RAW 뱅크 패킷이 더 저렴함
  → 뱅크 패킷
그 밖에 선택된 행에 단일 이벤트 타일이 있음
  → SPARSE 한 워드
그 밖의 경우
  → 기존 행 RAW
```

SPARSE와 BIN을 같은 뱅크 패킷에 섞으면 SPARSE 위치를 표시할 마스크가 하나 더 필요하다. 현재 구현은 이 오버헤드를 피하기 위해 두 형식을 독립 경로로 유지한다.

## 3. 회로 오버헤드 억제

1. RAW/GROUP3/BIN4/SPARSE를 서로 다른 인코더로 만들지 않고 하나의 2×2 분류기에서 함께 판정한다.
2. SPARSE 좌표를 타일마다 별도 레지스터에 저장하지 않는다. 기존 RAW8 비트맵과 내부 표시 비트 하나로 다시 계산한다.
3. 기존 손실형 패커의 16타일 가변 위치 패킹을 제거했다. 네 타일씩 최대 32비트를 만들어 48비트 저장소에 이어 붙이고, 준비된 16비트부터 순서대로 출력한다.
4. SPARSE와 손실형 뱅크 패킷은 같은 타일 저장공간, 행 순환 중재기, 상위 선택기와 출력 링크를 공유한다.

순차 패킹은 일부 패턴에 내부 준비 클록을 추가하지만, 한 클록에 16타일의 1비트·8비트 토큰을 모두 배치하던 큰 가변 선택 회로를 없앤다.

## 4. 기능 검증

### 단위·회귀 시험

- Python 단위 시험: 31개 통과
- Vivado 2024.1 XSim 회귀: 15개 통과
- SPARSE 단위 시험: `bank=5`, `tile=0`, `pixel=2`, `ON`이 `0x0285` 한 워드로 출력
- 같은 결합 회로의 혼잡 시험: 기존 손실형 기준과 같은 `8177 00FF 007E 1910 0009` 다섯 워드 출력
- 역압 중에는 `valid/data/last`가 유지되고 마지막 워드에서만 타일 상태 해제

### RTL과 Python 클록 모델 일치

CIFAR10-DVS 처음 8,000이벤트를 100MHz 입력 일정으로 재생한 결과 두 모델이 다음 수치에서 일치했다.

| 지표 | RTL XSim | Python |
|---|---:|---:|
| 입력 이벤트 | 8,000 | 8,000 |
| 받아들인 이벤트 | 7,406 | 7,406 |
| FIFO 무시 | 492 | 492 |
| 같은 클록 중복 | 102 | 102 |
| 받아들인 타일 그룹 | 5,172 | 5,172 |
| 출력 워드 | 4,183 | 4,183 |
| 복원 가짜 이벤트 | 163 | 163 |
| 패킷 오류 | 0 | 0 |

이 일치는 입력 비트맵, 픽셀 FIFO, 뱅크 수용 순서, 행 중재, 패킷 잠금과 링크 역압을 포함한다. 아래 전체 기록 결과는 같은 클록 모델로 측정했으며 전체 178,165이벤트에 대한 XSim 재실행 수치로 확대해서 표현하지 않는다.

## 5. CIFAR10-DVS 전체 기록 결과

공통 조건은 `airplane/0`의 178,165이벤트, 128×128센서, 2×2타일, 4×4타일 뱅크, 픽셀 FIFO 깊이 2, 16비트 단일 링크, 1297.016861배 재생이다. 전체 오류는 전송 전에 잃은 원본 이벤트와 손실형 복원으로 추가된 가짜 이벤트의 합이다.

### 100MHz 입력 일정

| 지표 | RAW | 손실형 | SPARSE+손실형 |
|---|---:|---:|---:|
| 받아들인 이벤트 | 140,110 | 156,096 | 160,089 |
| 전송 전 손실 | 38,055 | 22,069 | 18,076 |
| 복원 가짜 이벤트 | 0 | 3,748 | 3,069 |
| 전체 오류율 | 21.36% | 14.49% | 11.87% |
| 출력 워드 | 103,071 | 100,087 | 92,948 |

결합 구조는 RAW보다 출력 워드를 9.82% 줄였고, 전체 오류율을 9.49%p 낮췄다. RAW 대비 전체 오류의 상대 감소량은 44.44%다.

### 200MHz 입력 일정

| 지표 | RAW | 손실형 | SPARSE+손실형 |
|---|---:|---:|---:|
| 받아들인 이벤트 | 160,063 | 166,790 | 169,953 |
| 전송 전 손실 | 18,102 | 11,375 | 8,212 |
| 복원 가짜 이벤트 | 0 | 1,896 | 1,107 |
| 전체 오류율 | 10.16% | 7.45% | 5.23% |
| 출력 워드 | 178,503 | 162,819 | 132,130 |

결합 구조는 RAW보다 출력 워드를 25.98% 줄였고, 전체 오류율을 4.93%p 낮췄다. RAW 대비 전체 오류의 상대 감소량은 48.52%다.

## 6. 논리합성 결과

Vivado 2024.1, `xc7z020clg484-1`, 5ns 제약에서 `aer_bank_row_reader` 한 개를 배치·배선 전 논리합성했다. 128×128 전체 회로의 PPA가 아니라 한 뱅크의 구조 비교다.

| 지표 | RAW | 손실형 | 기존 SPARSE+손실형 | 면적 최적화 SPARSE+손실형 |
|---|---:|---:|---:|---:|
| LUT | 304 | 1,140 | 1,760 | 1,201 |
| FF | 266 | 411 | 435 | 318 |
| MUXF | 0 | 15 | 13 | 23 |
| 데이터 경로 지연 | 5.118ns | 13.716ns | 20.133ns | 12.639ns |
| 5ns 제약 최악 여유 | -0.125ns | -8.723ns | -15.140ns | -7.646ns |
| 지연 역수 참고값 | 약 195.4MHz | 약 72.9MHz | 약 49.7MHz | 약 79.1MHz |

손실형에 SPARSE를 추가한 순수 오버헤드는 LUT 620개, 54.4%와 FF 24개, 5.8%다. FF 증가는 작지만, 단일 이벤트를 찾고 뱅크 융합과 비교하는 조합 논리가 비용 계산 경로에 붙으면서 데이터 경로 지연은 46.8% 증가했다. 따라서 현재 병목은 SPARSE 좌표 저장량보다 `pending → 비용 계산·경로 선택 → 패커 상태`의 긴 조합 경로다.

중복 SPARSE 좌표 레지스터를 없애기 전 결합 구조는 FF 483개였으나, RAW8 상태에서 좌표를 다시 계산하도록 바꾼 뒤 435개로 48개 줄었다. 또한 비활성 기능의 레지스터 갱신을 매개변수로 막아 RAW 기준선에서 사용하지 않는 뱅크 패커가 제거되도록 했다.

이후 외부 수신 Timestamp와 결합 정책만 지원하는 전용 코어 `aer_bank_row_reader_combined_opt`를 분리했다. RAW8은 한 번만 저장하고 형식·payload·delta·행 기준시각의 중복 레지스터를 제거했으며, 패킷 비용은 5~8비트의 제한된 카운터로 계산했다. 기존 결합 코어와 비교하면 LUT는 31.8%, FF는 26.9%, 데이터 경로 지연은 37.2% 감소했다. 동일한 CIFAR10-DVS 8,000이벤트 시험에서 받아들인 이벤트 7,406개, 출력 워드 4,183개, 가짜 이벤트 163개와 패킷 오류 0건이 그대로 재현돼 전송 동작은 변하지 않았다.

다만 최적화 코어도 5ns 제약은 만족하지 못한다. 최장 경로는 여전히 `pending`에서 비용·패킷 선택을 거쳐 패커 비트 수 레지스터로 이어진다. 따라서 100/200MHz 달성을 위해서는 스냅숏과 형식 선택 사이에 파이프라인 경계를 추가해야 한다.

순차 패커 자체의 효과는 구조 변경 전 손실형 결과와 비교하면 분명하다. LUT는 20,120개에서 1,140개로 94.3%, 데이터 경로 지연은 27.103ns에서 13.716ns로 49.4% 줄었다. 다만 손실형과 결합형 모두 200MHz를 만족하지 못하며, 결합형은 100MHz도 만족하지 못한다.

## 7. 해석과 남은 일

- SPARSE는 희소한 타일에서 헤더 반복을 줄이고, 손실형 BIN은 집중된 타일에서 데이터 비트를 줄인다. 두 방식은 서로 다른 입력 분포를 담당하므로 결합 효과가 있다.
- 8,000이벤트의 짧은 구간에서는 가짜 이벤트 때문에 결합 구조의 오류율이 RAW보다 나빴다. 전체 기록에서 좋아졌다는 결과를 모든 구간의 보편적 이득으로 해석하면 안 된다.
- 현재 가장 긴 경로는 패킷 데이터 자체가 아니라 `pending → 비용 계산·경로 선택 → 패커 상태`다. 목표 주파수를 높이려면 스냅숏 저장, 비용 계산, 패킷 선택을 단계로 나눠야 한다.
- 다음 구현은 한 뱅크에서 먼저 100MHz를 만족시킨 뒤 128×128 전체 선택기까지 확장하고, 배치·배선 후 타이밍과 전력을 측정한다.
