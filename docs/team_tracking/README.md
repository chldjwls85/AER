# `/tmp` 팀 동향 일일 추적

공유 서버 `/tmp`에 남은 다른 계정의 AER 연구 산출물을 읽기 전용으로 확인하고, 전날 보고서와 비교해 의미 있는 변화만 기록한다.

## 운영 규칙

- `/tmp`와 `/home/aiasic26230/LVMOS/eojin` 바깥은 항상 읽기 전용으로 다룬다.
- 다른 팀의 원본 파일을 복사하거나 수정·삭제하지 않는다.
- 캐시, Cadence `genus_temp_*`, Xcelium 실행 디렉터리만으로 연구 방향을 단정하지 않는다.
- 문서, RTL 모듈명, 테스트 PASS/FAIL, 합성·P&R 보고서가 서로 맞을 때만 확정적으로 기록한다.
- 새 파일, 수정 파일, 사라진 파일을 구분한다. `/tmp`에서 파일이 사라진 것은 연구 철회가 아니라 임시 자료 정리일 수 있다고 표시한다.
- 100MB가 넘는 파일은 전체 해시를 계산하지 않고 소유자·크기·수정시각·파일명으로만 추적한다.
- 계정 번호와 공개된 팀명만 기록하고 개인 이름이나 인증 정보는 기록하지 않는다.

## Git 규칙

- 전용 저장소: `/home/aiasic26230/LVMOS/eojin/team-tracking`
- 전용 브랜치: `codex/daily-team-tracking`
- 보고서 위치: `docs/team_tracking/YYYY-MM-DD.md`
- 해당 날짜 보고서와 이 디렉터리의 인덱스만 stage한다. 다른 변경은 절대 함께 commit하지 않는다.
- 변화가 없는 날도 `변화 없음`을 명시한 날짜별 보고서를 만든다.
- 날짜별 보고서는 `chore: update team tracking YYYY-MM-DD` 형식으로 commit하고 `origin/codex/daily-team-tracking`에 push한다. 같은 날짜에 다시 실행해 내용이 동일하면 빈 commit은 만들지 않는다.

## 저장공간 정리 규칙

- 먼저 `/home`과 `/tmp`의 사용량을 기록한다.
- 자동 삭제는 `/home/aiasic26230/LVMOS/eojin` 최상위의 `core.*` 중 `file` 명령으로 ELF core dump임이 확인된 파일로 한정한다.
- RTL, 문서, Git 객체, 합성·P&R 보고서, `aer/build`, `aer/fv`, 인증 키는 자동 삭제하지 않는다.
- 그 외 대용량 후보는 보고서에 경로와 크기만 적고 사용자 승인 없이 삭제하지 않는다.
