# AER v1: 128×128 행·열 건너뛰기 구조

## 1. 이번 RTL의 입력 가정

- 센서 크기: 128×128픽셀
- 타일: 2×2픽셀
- 한 타일 입력: `ON[3:0]`, `OFF[3:0]`, `valid`
- 네 픽셀은 한 캡처 시점에 함께 읽은 비트맵이다.
- `valid && ready`인 클록에서만 입력을 받는다.
- ON과 OFF가 같은 픽셀에서 동시에 1이면 압축하지 않고 RAW로 보낸다.

이 버전의 시각은 센서의 아날로그 임계값 통과 순간이 아니라, 타일 비트맵을 회로가 받아들인 클록이다. 실제 픽셀 발생 시각을 보존하려면 센서 앞단이 별도의 캡처 시각을 제공해야 한다.

## 2. 계층 구조

```text
128×128 픽셀
│
├─ 2×2 픽셀 = 타일 1개
│  └─ 총 64×64 = 4,096타일
│
├─ 4×4 타일 = 뱅크 1개
│  └─ 뱅크 하나가 8×8픽셀 담당
│
├─ 16×16 뱅크 배열 = 총 256뱅크
│  ├─ 뱅크 내부: 타일 행을 순환 순서로 선택
│  └─ 선택한 행 내부: 열 0→1→2→3 순서로 전송
│
└─ 전역 출력
   ├─ bank_id = bank_row × 16 + bank_col
   ├─ 현재 위치부터 행 우선 순서로 다음 유효 뱅크 검색
   ├─ 이벤트가 없는 뱅크는 전송하지 않음
   └─ 선택 뱅크의 마지막 워드까지 선택을 고정
```

뱅크 번호는 `(0,0), (0,1), …, (0,15), (1,0), …, (15,15)` 순서다. 한 바퀴를 돈 뒤에는 다시 `(0,0)`으로 돌아간다. 따라서 항상 0번부터 다시 시작하는 고정 우선순위가 아니라, 마지막으로 서비스한 뱅크 다음 위치부터 이어서 찾는 순환 행 우선 방식이다.

## 3. 타일 인코딩 조건

`aer_tile_bitmap_encoder`의 `ENABLE_BINNING`으로 두 비교 모드를 만든다. 적응형은 `1`, 무비닝 RAW8 기준선은 `0`이다. 자세한 공통 조건은 [AER v1 공정 비교 규약](AER_v1_공정비교_규약.md)에 고정한다.

| 조건 | 형식 | 보존 정보 |
|---|---|---|
| ON 또는 OFF 네 개가 모두 1 | `BIN4` | 극성과 네 픽셀 전체 발생 |
| 한 극성만 세 개가 1 | `GROUP3` | 극성과 이벤트가 없는 픽셀 위치 |
| 그 밖의 조합 | `RAW8` | ON 4비트와 OFF 4비트 원본 |
| 같은 픽셀이 ON과 OFF 동시 1 | `RAW8` | 충돌 표시와 원본 |

단순 개수만 보내는 방식은 위치를 잃는다. 특히 0~4를 나타내려면 개수 하나당 3비트가 필요하므로 ON 개수 2비트와 OFF 개수 2비트만으로는 네 개를 표현할 수 없다. 이번 RTL은 `3-of-4`에서 빠진 위치까지 보존한다.

## 4. 16비트 출력 패킷

뱅크는 이벤트가 있는 타일 행 하나를 다음과 같이 보낸다.

```text
헤더 1워드
→ 행 기준 시각 1워드
→ 이벤트가 있는 열의 타일 워드 1~4개
```

### 헤더

```text
[15:14] 11
[13:6]  bank_id
[5:4]   뱅크 내부 tile_row
[3:0]   해당 행의 유효 열 비트맵
```

### 타일 워드

```text
[15:14] 형식: RAW8=00, GROUP3=01, BIN4=10
[13:10] 행 기준 시각과의 차이: 0~15클록
[9:2]   형식별 payload
[1]     RAW ON/OFF 충돌 표시
[0]     예약
```

행에서 첫 타일을 받을 때 16비트 기준 시각을 한 번 저장한다. 같은 행의 다른 타일은 4비트 시간차만 저장하므로 타일마다 16비트 전체 시각을 반복하지 않는다. 시간차가 15클록을 넘은 새 타일은 기존 행 패킷을 먼저 비운 뒤 새 기준 시각으로 받는다.

## 5. 좌표와 평탄화 순서

전역 타일 좌표가 `(tile_y, tile_x)`일 때 다음과 같이 입력 비트 위치를 구한다.

```text
bank_row  = tile_y / 4
bank_col  = tile_x / 4
bank_id   = bank_row × 16 + bank_col
local_row = tile_y % 4
local_col = tile_x % 4
local_id  = local_row × 4 + local_col
flat_id   = bank_id × 16 + local_id
```

`aer_v1_top_128`의 `tile_in_valid[flat_id]`, `tile_on_flat[flat_id*4 +: 4]`, `tile_off_flat[flat_id*4 +: 4]`가 한 타일 입력이다.

## 6. RTL 파일

- `rtl/v1/aer_tile_bitmap_encoder.v`: RAW8/GROUP3/BIN4 선택
- `rtl/v1/aer_locked_rr_arbiter.v`: 마지막 워드까지 고정하는 순환 선택기
- `rtl/v1/aer_bank_row_reader.v`: 4×4 타일 뱅크의 행 패킷 생성
- `rtl/v1/aer_global_bank_selector.v`: 16×16 뱅크 행 우선 선택과 빈 뱅크 건너뛰기
- `rtl/v1/aer_v1_top_128.v`: 전체 128×128 연결
- `rtl/v1/aer_v1_raw_top_128.v`: 같은 core를 사용하는 무비닝 RAW8 기준 top
- `tb/v1/`: 단위 시험과 전체 연결 시험
- `scripts/run_v1_xsim.ps1`: 로컬 Vivado XSim 기능 시뮬레이션

## 7. 현재 한계

- 타일당 대기 슬롯은 하나이므로 같은 타일의 다음 입력은 현재 토큰이 빠질 때까지 기다려야 한다.
- 출력은 16비트 단일 링크라 최대 처리량은 한 클록당 한 워드다.
- 빈 뱅크를 찾는 것은 한 클록에 조합 논리로 수행한다. 256입력 우선순위 경로의 타이밍이 길면 이후 16개씩 나눈 2단 선택기로 바꿔야 한다.
- `GROUP3`와 `BIN4`도 RAW8과 동일한 16비트 타일 워드 하나를 쓴다. 현재 적응형과 무비닝 기준선의 출력 워드 수와 링크 처리량은 같으며, 실제 전송량 이득을 내려면 여러 토큰을 한 워드에 넣는 추가 패킹이 필요하다.

## 8. 기능 시뮬레이션

2026년 8월 20일 로컬 Vivado 2024.1 XSim에서 다음 시험을 실행해 모두 통과했다.

- 타일 RAW8/GROUP3/BIN4 조건과 충돌 처리
- 선택 뱅크 잠금, 빈 뱅크 건너뛰기, 행 우선 순환
- 뱅크 행 헤더, 열 오름차순, 기준 시각과 4비트 시간차
- 128×128 전체 연결에서 한 이벤트의 3워드 패킷 출력
- 적응형과 무비닝 encoder의 허용된 DATA 차이
- 두 뱅크의 ready/valid/last, pending, 헤더, 시간, 워드 수 일치
- 무비닝 128×128 top의 RAW8 출력

이번 단계에서는 합성을 실행하거나 PPA 수치를 주장하지 않는다.
