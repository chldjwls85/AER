# AER v1: 크기 가변형 균형 계층 readout

## 1. 이번 RTL의 입력 가정

- 기본 센서 크기: 128×128픽셀
- 타일: 2×2픽셀
- 한 타일 입력: `ON[3:0]`, `OFF[3:0]`, `valid`
- 네 픽셀은 한 캡처 시점에 함께 읽은 비트맵이다.
- `valid && ready`인 클록에서만 입력을 받는다.
- ON과 OFF가 같은 픽셀에서 동시에 1이면 압축하지 않고 RAW로 보낸다.

이 버전의 시각은 센서의 아날로그 임계값 통과 순간이 아니라, 타일 비트맵을 회로가 받아들인 클록이다. 실제 픽셀 발생 시각을 보존하려면 센서 앞단이 별도의 캡처 시각을 제공해야 한다.

## 2. 계층 구조

```text
128×128 픽셀
│
├─ 2×2 픽셀 = 타일 1개
│  └─ 총 64×64 = 4,096타일
│
├─ 4×4 타일 = 뱅크 1개
│  └─ 뱅크 하나가 8×8픽셀 담당
│
├─ 16×16 뱅크 배열 = 총 256뱅크
│  ├─ 뱅크 내부: 타일 행을 순환 순서로 선택
│  └─ 선택한 행 내부: 열 0→1→2→3 순서로 전송
│
├─ 4×4 인접 뱅크 = 지역 selector 한 개
│  └─ selector와 2-entry 탄력 FIFO를 단계마다 반복
│
└─ 전역 출력: 4×4 지역 selector를 거쳐 한 root로 수렴
```

`aer_v1_top`의 `SENSOR_ROWS`, `SENSOR_COLS`가 타일과 뱅크 배열 수를 정한다. 두 값은 현재 고정 leaf 크기인 8×8픽셀 뱅크의 배수여야 한다. `REGION_BANK_ROWS`, `REGION_BANK_COLS`는 selector 하나가 담당하는 공간적으로 인접한 하위 블록 수다. 기본값 4×4에서는 각 request encoder와 data MUX의 fan-in이 최대 16으로 제한된다.

각 축의 상위 노드 수는 `ceil(하위 노드 수 / REGION_BANK_SIZE)`로 계산한다. 한 노드만 남을 때까지만 단계를 생성하므로 작은 센서에는 불필요한 단계가 생기지 않고, 큰 센서는 배열 fan-in을 키우는 대신 등록된 상위 단계를 추가한다. 기본 128×128 구성은 `16×16 bank → 4×4 region → 1 root`의 2단 selector다. 각 selector는 패킷의 마지막 워드까지 선택을 고정하며, look-ahead grant로 다음 패킷 선택에 빈 클록을 넣지 않는다.

## 3. 타일 인코딩 조건

| 조건 | 형식 | 보존 정보 |
|---|---|---|
| ON 또는 OFF 네 개가 모두 1 | `BIN4` | 극성과 네 픽셀 전체 발생 |
| 한 극성만 세 개가 1 | `GROUP3` | 극성과 이벤트가 없는 픽셀 위치 |
| 그 밖의 조합 | `RAW8` | ON 4비트와 OFF 4비트 원본 |
| 같은 픽셀이 ON과 OFF 동시 1 | `RAW8` | 충돌 표시와 원본 |

단순 개수만 보내는 방식은 위치를 잃는다. 특히 0~4를 나타내려면 개수 하나당 3비트가 필요하므로 ON 개수 2비트와 OFF 개수 2비트만으로는 네 개를 표현할 수 없다. 이번 RTL은 `3-of-4`에서 빠진 위치까지 보존한다.

## 4. 16비트 출력 패킷

뱅크는 이벤트가 있는 타일 행 하나를 다음과 같이 보낸다.

```text
헤더 1워드
→ 행 기준 시각 1워드
→ 이벤트가 있는 열의 타일 워드 1~4개
```

### 헤더

```text
[15:14] 11
[13:6]  bank_id
[5:4]   뱅크 내부 tile_row
[3:0]   해당 행의 유효 열 비트맵
```

### RAW8와 GROUP3 타일 워드

```text
[15:14] 형식: RAW8=00, GROUP3=01
[13:10] 행 기준 시각과의 차이: 0~15클록
[9:2]   형식별 payload
[1]     RAW ON/OFF 충돌 표시
[0]     예약
```

### BIN4 단일·쌍 패킹 워드

헤더의 유효 열 비트맵과 열 오름차순 전송 규칙으로 타일 열을 알 수 있으므로 BIN4에는 열 주소를 반복하지 않는다.

```text
[15:14] 10: BIN4
[13]    0: 단일 BIN, 1: BIN 두 개 패킹

단일 BIN:
[12:9]  시간차
[8]     극성
[7:0]   예약

BIN 쌍:
[12:9]  첫 번째 시간차
[8]     첫 번째 극성
[7:4]   두 번째 시간차
[3]     두 번째 극성
[2:0]   예약
```

따라서 한 행의 네 타일이 모두 BIN4이면 기존 네 데이터 워드 대신 두 데이터 워드로 전송한다. 헤더와 기준 시각을 포함하면 `6워드 → 4워드`가 된다. 4×4픽셀을 하나의 BIN16으로 합치는 기능은 이번 버전에 포함하지 않는다.

행에서 첫 타일을 받을 때 16비트 기준 시각을 한 번 저장한다. 같은 행의 다른 타일은 4비트 시간차만 저장하므로 타일마다 16비트 전체 시각을 반복하지 않는다. 시간차가 15클록을 넘은 새 타일은 기존 행 패킷을 먼저 비운 뒤 새 기준 시각으로 받는다.

뱅크가 256개를 넘으면 기본 헤더 다음에 `BANK_ID[15:8]`을 담은 확장 주소 워드를 한 개 추가한다. 256개 이하에서는 기존 3워드 최소 패킷 구조를 유지한다.

## 5. 좌표와 평탄화 순서

전역 타일 좌표가 `(tile_y, tile_x)`일 때 다음과 같이 입력 비트 위치를 구한다.

```text
bank_row  = tile_y / 4
bank_col  = tile_x / 4
BANK_COLS = SENSOR_COLS / 8
bank_id   = bank_row × BANK_COLS + bank_col
local_row = tile_y % 4
local_col = tile_x % 4
local_id  = local_row × 4 + local_col
flat_id   = bank_id × 16 + local_id
```

`aer_v1_top_128`의 `tile_in_valid[flat_id]`, `tile_on_flat[flat_id*4 +: 4]`, `tile_off_flat[flat_id*4 +: 4]`가 한 타일 입력이다.

## 6. RTL 파일

- `rtl/v1/aer_tile_bitmap_encoder.v`: RAW8/GROUP3/BIN4 선택
- `rtl/v1/aer_locked_rr_arbiter.v`: look-ahead와 패킷 잠금을 지원하는 순환 선택기
- `rtl/v1/aer_stream_fifo2.v`: 계층 사이의 2-entry 탄력 FIFO
- `rtl/v1/aer_balanced_selector_tree.v`: 공간 기반 가변 깊이 selector tree
- `rtl/v1/aer_bank_row_reader.v`: BIN 쌍 패킹을 포함한 4×4 타일 뱅크
- `rtl/v1/aer_global_bank_selector.v`: 균형 selector tree 래퍼
- `rtl/v1/aer_v1_top_128.v`: 크기 가변 `aer_v1_top`과 128×128 호환 래퍼
- `tb/v1/`: 단위 시험과 전체 연결 시험
- `scripts/run_v1_xsim.ps1`: 로컬 Vivado XSim 기능 시뮬레이션
- `scripts/run_v1_xcelium.sh`: 서버 Xcelium 기능 시뮬레이션

## 7. 현재 한계

- 타일당 대기 슬롯은 하나이므로 같은 타일의 다음 입력은 현재 토큰이 빠질 때까지 기다려야 한다.
- 출력은 16비트 단일 링크라 최대 처리량은 한 클록당 한 워드다.
- 2×2 BIN4 두 개만 패킹하며, 4×4 BIN16과 일반 가변 길이 비트 패커는 아직 없다.
- selector fan-in은 제한했지만 실제 목표 주파수는 합성 및 배치·배선 후 확인해야 한다.
- 기본 구성은 최대 4개 selector 단계를 생성하며, 더 큰 배열은 트리 단계 확장이 필요하다.

## 8. 기능 시뮬레이션

2026년 8월 20일 Xcelium 23.09-s013에서 다음 시험을 실행해 모두 통과했다.

- 타일 RAW8/GROUP3/BIN4 조건과 충돌 처리
- BIN4 두 개 패킹, 단일 BIN, GROUP3, 시간차 제한
- 2단 공간 selector, 패킷 잠금, 패킷 경계 zero-bubble 전송
- 2-entry 출력 FIFO의 backpressure 데이터 안정성
- 16비트 확장 뱅크 주소
- 24×40 센서, 3×5 뱅크, 3단 selector의 비정규 배열 생성
- 128×128 전체 연결에서 한 이벤트의 3워드 패킷 출력

이번 단계에서는 합성을 실행하거나 PPA 수치를 주장하지 않는다.
