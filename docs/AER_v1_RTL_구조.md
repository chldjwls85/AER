# AER v1: 크기 가변형 균형 계층 readout

> 128×128 영역 공유 압축 구조와 공정 RAW 비교의 최신 XSim 결과는
> [AER v1 영역 공유 압축 구조와 XSim 검증](AER_v1_공유압축_최적화_XSim.md)을
> 기준으로 한다.

## 1. 이번 RTL의 입력 가정

- 기본 센서 크기: 128×128픽셀
- 타일: 2×2픽셀
- 한 타일 입력: `ON[3:0]`, `OFF[3:0]`, `valid`
- 네 픽셀은 한 캡처 시점에 함께 읽은 비트맵이다.
- `valid && ready`인 클록에서만 입력을 받는다.
- ON과 OFF가 같은 픽셀에서 동시에 1이면 압축하지 않고 RAW로 보낸다.

기본 모드의 시각은 센서의 아날로그 임계값 통과 순간이 아니라, 타일 비트맵을 회로가 받아들인 클록이다. 실제 픽셀 발생 시각을 보존하려면 센서 앞단이 별도의 캡처 시각을 제공해야 한다.

CIFAR10-DVS 검증에는 `aer_pixel_pending_array`를 센서 앞단 모델로 붙였다. 각 픽셀은 아직 읽히지 않은 이벤트 하나와 극성 하나만 보관한다. 해당 픽셀이 대기 중일 때 들어온 다음 이벤트는 무시하고, 타일의 `valid && ready`가 성립하면 네 픽셀을 읽은 것으로 보고 대기 상태를 해제한다. 같은 클록에 해제와 새 이벤트가 겹치면 새 이벤트를 다음 대기 값으로 받는다.

## 2. 계층 구조

```text
128×128 픽셀
│
├─ 2×2 픽셀 = 타일 1개
│  └─ 총 64×64 = 4,096타일
│
├─ 4×4 타일 = 뱅크 1개
│  └─ 뱅크 하나가 8×8픽셀 담당
│
├─ 16×16 뱅크 배열 = 총 256뱅크
│  ├─ 기본: 타일 행을 순환 선택한 뒤 열 0→1→2→3 전송
│  └─ 선택: 이득이 있을 때 현재 뱅크의 동종 타일을 한 패킷으로 전송
│
├─ 4×4 인접 뱅크 = 지역 selector 한 개
│  └─ selector와 2-entry 탄력 FIFO를 단계마다 반복
│
└─ 전역 출력: 4×4 지역 selector를 거쳐 한 root로 수렴
```

`aer_v1_top`의 `SENSOR_ROWS`, `SENSOR_COLS`가 타일과 뱅크 배열 수를 정한다. 두 값은 현재 고정 leaf 크기인 8×8픽셀 뱅크의 배수여야 한다. `REGION_BANK_ROWS`, `REGION_BANK_COLS`는 selector 하나가 담당하는 공간적으로 인접한 하위 블록 수다. 기본값 4×4에서는 각 request encoder와 data MUX의 fan-in이 최대 16으로 제한된다.

각 축의 상위 노드 수는 `ceil(하위 노드 수 / REGION_BANK_SIZE)`로 계산한다. 한 노드만 남을 때까지만 단계를 생성하므로 작은 센서에는 불필요한 단계가 생기지 않고, 큰 센서는 배열 fan-in을 키우는 대신 등록된 상위 단계를 추가한다. 기본 128×128 구성은 `16×16 bank → 4×4 region → 1 root`의 2단 selector다. 각 selector는 패킷의 마지막 워드까지 선택을 고정하며, look-ahead grant로 다음 패킷 선택에 빈 클록을 넣지 않는다.

## 3. 타일 인코딩 조건

`aer_tile_bitmap_encoder`의 `ENABLE_BINNING`으로 기본 무손실 비닝과 무비닝 RAW8 기준선을 선택한다. `ENABLE_LOSSY_BINNING=1`이면 뱅크 패커가 GROUP3와 BIN4를 같은 BIN 토큰으로 취급하는 손실형 정책을 추가로 적용한다. `ENABLE_SPARSE=1`이면 같은 분류기에서 이벤트가 정확히 하나인 타일도 찾아 손실 없는 단일 워드 SPARSE 패킷 후보로 사용한다. 자세한 공통 조건은 [AER v1 공정 비교 규약](AER_v1_공정비교_규약.md)에 고정한다.

| 조건 | 형식 | 보존 정보 |
|---|---|---|
| ON 또는 OFF 네 개가 모두 1 | `BIN4` | 극성과 네 픽셀 전체 발생 |
| 한 극성만 세 개가 1 | `GROUP3` | 극성과 이벤트가 없는 픽셀 위치 |
| 그 밖의 조합 | `RAW8` | ON 4비트와 OFF 4비트 원본 |
| 같은 픽셀이 ON과 OFF 동시 1 | `RAW8` | 충돌 표시와 원본 |
| ON 또는 OFF 이벤트가 정확히 하나 | `SPARSE` 후보 | 타일·픽셀 위치와 극성 |

단순 개수만 보내는 방식은 위치를 잃는다. 특히 0~4를 나타내려면 개수 하나당 3비트가 필요하므로 ON 개수 2비트와 OFF 개수 2비트만으로는 네 개를 표현할 수 없다. 기본 무손실 RTL은 `3-of-4`에서 빠진 위치까지 보존한다. 손실형 모드에서는 전송 워드가 실제로 줄어드는 경우에만 빠진 위치를 버리고 수신 측에서 네 픽셀로 복원한다.

## 4. 16비트 출력 패킷

뱅크는 이벤트가 있는 타일 행 하나를 다음과 같이 보낸다.

```text
헤더 1워드
→ 행 기준 시각 1워드
→ 이벤트가 있는 열의 타일 워드 1~4개
```

`EXTERNAL_RX_TIMESTAMP=1`인 외부 수신 시각 모드에서는 행 기준 시각 워드를 보내지 않는다. 수신기는 패킷의 첫 헤더 워드가 도착한 출력 클록을 그 패킷의 시각으로 기록한다. 따라서 서로 다른 픽셀의 원래 발생 시각을 하나로 섞어 대표값을 만드는 문제가 없지만, 센서 발생 시각 자체는 보존하지 않고 readout 지연이 포함된다는 한계가 있다.

`ENABLE_ROW_FUSION=1`은 이 외부 수신 시각 모드에서만 동작한다. 중재기는 그대로 행을 선택하고, 선택 당시 유효 열이 모두 BIN4 또는 모두 GROUP3일 때 DATA를 한 워드로 바꾼다. 추가 이벤트를 기다리거나 뱅크 우선순위를 바꾸지 않는다.

`ENABLE_BANK_FUSION=1`도 외부 수신 시각 모드에서만 동작한다. 행 선택기가 한 뱅크의 전송을 시작하는 순간, 그 뱅크에 이미 대기 중인 16타일 전체를 스냅숏한다. 동종 형식이고 실제 출력 워드 수가 기존 행 패킷보다 작을 때만 뱅크 패킷을 선택한다. 압축을 위해 기다리거나 중재 우선순위를 바꾸지 않는다.

### 헤더

```text
[15:14] 11
[13:6]  bank_id
[5:4]   뱅크 내부 tile_row
[3:0]   해당 행의 유효 열 비트맵
```

### RAW8와 GROUP3 타일 워드

```text
[15:14] 형식: RAW8=00, GROUP3=01
[13:10] 행 기준 시각과의 차이: 0~15클록
[9:2]   형식별 payload
[1]     RAW ON/OFF 충돌 표시
[0]     예약
```

### BIN4 단일·쌍 패킹 워드

헤더의 유효 열 비트맵과 열 오름차순 전송 규칙으로 타일 열을 알 수 있으므로 BIN4에는 열 주소를 반복하지 않는다.

```text
[15:14] 10: BIN4
[13]    0: 단일 BIN, 1: BIN 두 개 패킹

단일 BIN:
[12:9]  시간차
[8]     극성
[7:0]   예약

BIN 쌍:
[12:9]  첫 번째 시간차
[8]     첫 번째 극성
[7:4]   두 번째 시간차
[3]     두 번째 극성
[2:0]   예약
```

따라서 한 행의 네 타일이 모두 BIN4이면 기존 네 데이터 워드 대신 두 데이터 워드로 전송한다. 헤더와 기준 시각을 포함하면 `6워드 → 4워드`가 된다. 4×4픽셀을 하나의 BIN16으로 합치는 기능은 이번 버전에 포함하지 않는다.

### 행 융합 워드

헤더를 받은 수신기는 유효 열 위치를 이미 알고 있다. 외부 수신 시각 모드에서는 타일별 시간차도 사용하지 않으므로 예약 형식 `11`을 DATA 단계에서 행 융합 표시로 재사용한다. 패킷 단계가 헤더와 DATA를 구분한다.

```text
공통:
[15:14] 11 = DATA 단계 행 융합
[13]    0 = ROW_BIN4, 1 = ROW_GROUP3

ROW_BIN4:
[12:9]  열 3~0의 극성 비트
[8:0]   예약

ROW_GROUP3:
[12:1]  열마다 {극성, 빠진 픽셀 위치[1:0]} 3비트
[0]     예약
```

동종 행이 아니면 기존 BIN4 단일·쌍, GROUP3, RAW8 전송으로 자동 복귀한다. 행 융합 워드에 포함된 모든 타일은 원래부터 같은 헤더의 외부 수신 시각을 공유하므로 별도의 대표 시각을 만들지 않는다.

### 뱅크 융합 패킷

뱅크 패킷은 패킷 시작 단계에서 상위 2비트 `10`을 사용한다. 같은 값은 행 DATA 단계의 BIN4에도 쓰이지만, 수신기는 현재 패킷 단계로 헤더와 DATA를 구분한다.

```text
뱅크 헤더:
[15:14] 10 = 뱅크 패킷
[13:6]  bank_id
[5:4]   묶음 형식: RAW8=00, GROUP3=01, BIN4=10
[3:0]   유효 타일 수 - 1

위치 마스크:
[15:0]  뱅크 내부 local_tile 15~0의 유효 비트맵

묶음 데이터:
RAW8   = 유효 타일마다 {ON[3:0], OFF[3:0]} 8비트
GROUP3 = 유효 타일마다 {극성, 빠진 위치[1:0]} 3비트
BIN4   = 유효 타일마다 극성 1비트
```

유효 타일은 `local_tile=0→15` 순서로 빈틈없이 하위 비트부터 패킹한다. RAW8은 한 워드에 두 타일, GROUP3는 최대 다섯 타일, BIN4는 최대 16타일을 담는다. RAW8의 ON/OFF 충돌 표시가 하나라도 있거나 형식이 섞이면 기존 행 패킷으로 복귀한다.

### 손실형 혼합 뱅크 패킷

`ENABLE_BANK_FUSION=1`, `ENABLE_LOSSY_BINNING=1`, `EXTERNAL_RX_TIMESTAMP=1`일 때 형식이 섞인 타일도 한 뱅크 패킷에 담을 수 있다.

```text
뱅크 헤더 mode[1:0] = 11
→ 유효 타일 비트맵 16비트
→ BIN 타일 비트맵 16비트
→ local_tile 오름차순 가변 길이 데이터

BIN 타일: 극성 1비트
RAW 타일: {ON[3:0], OFF[3:0]} 8비트
```

한 극성의 이벤트가 세 개 또는 네 개 발생한 타일은 같은 BIN 극성 1비트로 표현한다. 세 개인 경우 수신 복원에서 가짜 이벤트가 한 개 생긴다. 회로는 `혼합 손실형`, `무손실 RAW 뱅크`, `행 RAW`의 정확한 워드 수를 비교한다. 혼합 패킷이 두 무손실 후보보다 모두 작을 때만 손실형을 선택하며, 동률이거나 이득이 없으면 무손실 RAW로 복귀한다.

가변 길이 데이터는 16타일 전체를 한 클록에 패킹하지 않는다. 네 타일씩 검사해 최대 32비트를 48비트 저장소에 이어 붙이고, 준비된 16비트부터 출력한다. 이 방식은 패킹에 몇 클록이 더 걸릴 수 있지만 16타일 가변 배럴 시프터를 제거한다.

선택 조건은 추정 밀도가 아니라 정확한 직렬화 비용이다.

```text
뱅크 비용 = 헤더 1 + 위치 마스크 1 + 묶음 데이터 워드 수
선택 조건 = 뱅크 비용 < 같은 스냅숏을 기존 행 패킷으로 보낼 비용
```

뱅크 패킷에 포함된 타일은 마지막 데이터 워드가 전송될 때 한꺼번에 해제한다. 따라서 비교군보다 추가 대기 슬롯을 얻지는 않지만, 최대 10워드 동안 한 뱅크 패킷이 링크 선택을 잠글 수 있다. 모든 타일의 기록 시각은 뱅크 헤더가 외부 링크에 도착한 클록이다.

### 희소 단일 이벤트 패킷

`ENABLE_SPARSE=1`, `EXTERNAL_RX_TIMESTAMP=1`일 때 2×2타일에 이벤트가 정확히 하나면 다음 16비트 한 워드로 전송할 수 있다.

```text
[15]    0 = SPARSE
[14:7]  bank_id
[6:3]   local_tile
[2:1]   pixel
[0]     polarity
```

기존 행 RAW는 이벤트 하나에도 헤더와 DATA 두 워드가 필요하지만 SPARSE는 한 워드이므로 희소 구간의 링크 점유를 절반으로 줄인다. 혼잡한 뱅크에서 손실형 융합이 더 저렴하면 SPARSE를 따로 섞지 않고 뱅크 패킷을 선택한다. SPARSE 여부는 별도 좌표 레지스터에 중복 저장하지 않고 기존 RAW8 상태와 내부 표시 비트로 관리한다.

행에서 첫 타일을 받을 때 16비트 기준 시각을 한 번 저장한다. 같은 행의 다른 타일은 4비트 시간차만 저장하므로 타일마다 16비트 전체 시각을 반복하지 않는다. 시간차가 15클록을 넘은 새 타일은 기존 행 패킷을 먼저 비운 뒤 새 기준 시각으로 받는다.

뱅크가 256개를 넘으면 행 패킷은 기본 헤더 다음에 `BANK_ID[15:8]`을 담은 확장 주소 워드를 한 개 추가한다. 현재 뱅크 융합 패킷은 8비트 `bank_id`, 즉 최대 256뱅크 구성에서만 활성화된다. 그보다 큰 구성은 행 패킷으로 자동 복귀한다.

## 5. 좌표와 평탄화 순서

전역 타일 좌표가 `(tile_y, tile_x)`일 때 다음과 같이 입력 비트 위치를 구한다.

```text
bank_row  = tile_y / 4
bank_col  = tile_x / 4
BANK_COLS = SENSOR_COLS / 8
bank_id   = bank_row × BANK_COLS + bank_col
local_row = tile_y % 4
local_col = tile_x % 4
local_id  = local_row × 4 + local_col
flat_id   = bank_id × 16 + local_id
```

`aer_v1_top_128`의 `tile_in_valid[flat_id]`, `tile_on_flat[flat_id*4 +: 4]`, `tile_off_flat[flat_id*4 +: 4]`가 한 타일 입력이다.

## 6. RTL 파일

- `rtl/v1/aer_tile_bitmap_encoder.v`: RAW8/GROUP3/BIN4와 손실 없는 SPARSE 후보를 함께 분류
- `rtl/frontend/aer_pixel_pending_array.v`: 픽셀당 1개 대기 이벤트와 ACK 해제를 모델링하는 센서 앞단
- `rtl/v1/aer_locked_rr_arbiter.v`: look-ahead와 패킷 잠금을 지원하는 순환 선택기
- `rtl/v1/aer_stream_fifo2.v`: 계층 사이의 2-entry 탄력 FIFO
- `rtl/v1/aer_balanced_selector_tree.v`: 공간 기반 가변 깊이 selector tree

## 7. 현재 한계

- 타일당 대기 슬롯은 하나이므로 같은 타일의 다음 입력은 현재 토큰이 빠질 때까지 기다려야 한다.
- CIFAR 센서 앞단 모델은 픽셀당 대기 슬롯이 하나여서, readout 전에 같은 픽셀에 다시 발생한 이벤트를 잃는다.
- 외부 수신 시각 모드는 발생 시각 대신 링크 도착 시각을 저장하므로 혼잡할수록 시각 오차가 커진다.
- 출력은 16비트 단일 링크라 최대 처리량은 한 클록당 한 워드다.
- 손실형 데이터 패킹은 네 타일씩 여러 클록에 나눴지만, 패킷 비용 계산과 SPARSE/뱅크/행 선택은 아직 같은 결정 경로에 있다. 200MHz를 목표로 하면 분류·비용 계산·패킷 선택 사이에 추가 파이프라인이 필요하다.
- 손실형 뱅크 패킷은 8비트 `bank_id`만 지원한다. 256뱅크를 넘는 구성에서는 행 RAW 경로로 복귀한다.
- 뱅크 패킷 잠금은 평균 지연을 줄일 수 있지만 다른 뱅크의 순간 최대 대기시간을 늘릴 수 있다.
- selector fan-in은 제한했지만 실제 목표 주파수는 합성 및 배치·배선 후 확인해야 한다.
- 기본 구성은 최대 4개 selector 단계를 생성하며, 더 큰 배열은 트리 단계 확장이 필요하다.

## 8. 기능 시뮬레이션

2026년 8월 20일 Xcelium 23.09-s013에서 다음 시험을 실행해 모두 통과했다.

- 타일 RAW8/GROUP3/BIN4 조건과 충돌 처리
- BIN4 두 개 패킹, 단일 BIN, GROUP3, 시간차 제한
- 2단 공간 selector, 패킷 잠금, 패킷 경계 zero-bubble 전송
- 2-entry 출력 FIFO의 backpressure 데이터 안정성
- 16비트 확장 뱅크 주소
- 24×40 센서, 3×5 뱅크, 3단 selector의 비정규 배열 생성
- 128×128 전체 연결에서 한 이벤트의 3워드 패킷 출력
- 적응형과 무비닝 encoder의 허용된 DATA 차이
- 공통 계층에서 적응형 BIN 패킹과 무비닝 RAW8의 출력 워드 수 비교
- 무비닝 128×128 top의 RAW8 출력

손실형 혼합 패킷 추가 후에는 한 뱅크 단위 Vivado 논리합성을 실행했다. 결과와 적용 범위는 [손실형 RTL·XSim·합성 검증](AER_손실형_RTL_XSim_합성_검증.md)에 분리해 기록하며, 이 수치를 128×128 전체 회로나 배치·배선 후 PPA로 확대하지 않는다.

같은 날 로컬 Vivado XSim 2024.1에서 CIFAR10-DVS 8,000이벤트의 혼잡 시험도 통과했다. 이 시험은 5,000배 재생 속도의 스트레스 조건이며 실제 센서의 일반 손실률을 뜻하지 않는다. 픽셀 대기 상태, ACK 해제, RAW8/GROUP3/BIN4 전송, 외부 수신 시각 부여와 패킷 복원을 끝까지 연결해 검사했으며 패킷 무결성 오류는 0건이었다.
