# AER v1 뱅크 융합 CIFAR10-DVS 비교

## 1. 결론

한 행 안에서만 합치는 것보다, 선택된 뱅크의 현재 대기 타일을 비용이 줄어드는 경우에만 한 패킷으로 묶는 편이 이번 혼잡 입력에서 효과가 컸다.

- 100MHz: 기존 비닝 대비 손실률 `20.679% → 18.472%`, 수용 이벤트 `+3,931개`
- 200MHz: 기존 비닝 대비 손실률 `10.068% → 7.953%`, 수용 이벤트 `+3,767개`
- 원본 ON/OFF 비트맵과 수신 복원 결과의 패킷 무결성 오류: 두 조건 모두 `0건`
- 합성은 실행하지 않았으므로 면적, 전력, 최대 주파수 개선은 아직 주장하지 않는다.

## 2. 뱅크 융합 규칙

행 하나가 선택되는 순간 해당 4×4타일 뱅크의 현재 대기 타일을 검사한다. 다음 조건을 모두 만족할 때만 뱅크 패킷을 사용한다.

1. 대기 타일이 모두 RAW8, 모두 GROUP3 또는 모두 BIN4 중 하나다.
2. RAW8이면 ON/OFF 충돌 표시가 없다.
3. `뱅크 헤더 + 위치 마스크 + 묶음 데이터`가 기존 행 패킷보다 실제로 적은 워드를 사용한다.

조건을 만족하지 않으면 기존의 행 선택과 열 오름차순 전송으로 복귀한다. 압축을 위해 기다리거나 특정 뱅크에 우선순위를 주지 않는다.

## 5. 실제로 무엇이 묶였는가

| 항목 | 100MHz | 200MHz |
|---|---:|---:|
| 뱅크 패킷 | 6,382개 | 12,034개 |
| 뱅크 패킷에 포함된 타일 | 29,828개 | 55,106개 |
| 패킷당 평균 타일 | 4.67개 | 4.58개 |
| 전체 수신 타일 중 뱅크 패킷 비율 | 36.50% | 44.79% |
| 같은 스냅숏의 기존 행 비용 대비 절감 워드 | 18,846개 | 34,922개 |

이번 입력에서는 뱅크 패킷의 대부분이 RAW8이었다.

```text
100MHz: RAW8 6,368패킷, GROUP3 1패킷, BIN4 13패킷
200MHz: RAW8 12,032패킷, GROUP3 1패킷, BIN4 1패킷
```

따라서 이번 개선의 주된 원인은 픽셀 비닝이 더 자주 발생한 것이 아니다. 여러 행에 흩어진 RAW 타일이 같은 뱅크에 있을 때 뱅크 주소와 행 헤더를 반복하지 않고, 두 RAW8 타일을 한 16비트 데이터 워드에 넣은 효과가 크다.

## 6. 중요한 대가

평균 지연과 99% 지연은 개선됐지만 최대 지연은 기존 비닝보다 100MHz에서 `15.5%`, 200MHz에서 `14.6%` 늘었다. 최대 10워드인 뱅크 패킷이 선택되면 마지막 워드까지 링크 선택이 잠기기 때문이다.

또한 모든 타일에 뱅크 헤더 수신 시각을 기록하므로 패킷 내부에서는 최대 9클록의 시각 뭉침이 생긴다. 이는 100MHz에서 90ns, 200MHz에서 45ns다. 현재처럼 외부 readout 시각을 쓰는 목적에는 사용할 수 있지만, 센서 발생 시각 보존이 필요하면 별도의 타임스탬프 규약이 필요하다.
