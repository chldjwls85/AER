# AER v1 공정 비교 규약

## 1. 비교 목적

타일 비닝과 상위 패킷 묶음의 효과를 분리해서 보기 위해 여섯 구조가 같은 데이터 경로를 공유한다. 계층과 중재기를 복사하지 않고 형식 선택 매개변수만 다르게 설정한다.

```text
뱅크 융합: ENABLE_BINNING=1, ENABLE_ROW_FUSION=0, ENABLE_BANK_FUSION=1
행 융합:   ENABLE_BINNING=1, ENABLE_ROW_FUSION=1, ENABLE_BANK_FUSION=0
기존 비닝: ENABLE_BINNING=1, ENABLE_ROW_FUSION=0, ENABLE_BANK_FUSION=0
무비닝:    ENABLE_BINNING=0, ENABLE_ROW_FUSION=0, ENABLE_BANK_FUSION=0
손실형:    ENABLE_BINNING=1, ENABLE_ROW_FUSION=0, ENABLE_BANK_FUSION=1,
           ENABLE_LOSSY_BINNING=1, ENABLE_SPARSE=0
결합형:    ENABLE_BINNING=1, ENABLE_ROW_FUSION=0, ENABLE_BANK_FUSION=1,
           ENABLE_LOSSY_BINNING=1, ENABLE_SPARSE=1
```

무비닝은 이벤트를 픽셀별 개수로 축약하지 않는다는 뜻이다. 한 번에 읽은 2×2 타일의 `ON[3:0]`과 `OFF[3:0]`을 8비트 RAW 비트맵으로 그대로 보존한다.

## 2. 반드시 동일하게 유지할 조건

| 항목 | 공통 사양 |
|---|---|
| 센서 | 128×128픽셀 |
| 타일 입력 | 2×2, `ON[3:0]`, `OFF[3:0]`, `valid/ready` |
| 뱅크 | 4×4타일, 총 16×16뱅크 |
| 뱅크 선택 | 행 우선 순환, 빈 뱅크 건너뛰기 |
| 뱅크 내부 읽기 | 유효 행 선택 후 열 오름차순 |
| 픽셀 입력 저장 | 비교 실험마다 동일 깊이 사용: 1-entry 또는 2-entry |
| 대기 공간 | 타일당 토큰 한 개 |
| 시간 | 동일 모드 사용: 행 기준 시각 또는 외부 링크 첫 워드 수신 시각 |
| 출력 물리 링크 | 16비트, 동일 `valid/ready/last` 규약 |
| 입력 | 같은 이벤트와 같은 클록에 동시 인가 |

두 구조는 같은 RTL 계층, 버퍼 깊이와 출력 링크를 사용한다. 적응형 구조는 연속된 BIN4 타일 두 개를 한 DATA 워드에 패킹할 수 있으므로, 패킹이 성립하는 입력에서는 DATA 워드 수와 이에 따른 `valid/last` 시점이 달라질 수 있다. 패킹되지 않는 입력에서는 타일 DATA 워드의 `format`과 `payload`만 다르다.

행 융합 비교에서도 뱅크 선택과 행 선택의 순환 중재기는 바꾸지 않는다. 선택된 행의 현재 타일만 검사하며, 압축 기회를 기다리거나 특정 뱅크의 우선순위를 높이지 않는다. 선택 당시 유효 열이 모두 BIN4 또는 모두 GROUP3일 때만 DATA 한 워드로 융합하고, 혼합 행은 기존 적응형 경로로 되돌아간다.

뱅크 융합도 입력을 기다리거나 뱅크 우선순위를 바꾸지 않는다. 행 하나가 선택되는 순간 그 뱅크에 이미 대기 중인 최대 16타일을 검사한다. 모든 타일 형식이 같고 `뱅크 헤더 + 위치 마스크 + 묶음 데이터`의 정확한 워드 수가 기존 행 패킷보다 작을 때만 뱅크 패킷을 사용한다. 혼합 형식, RAW 충돌 표시, 이득이 없는 경우에는 기존 행 경로로 자동 복귀한다. 뱅크 스냅숏은 마지막 데이터 워드에서 한 번에 해제하므로 숨은 추가 저장공간을 제공하지 않는다.

픽셀 입력부의 `PIXEL_FIFO_DEPTH`는 1 또는 2로 설정할 수 있다. 2-entry 비교에서도 적응형과 무비닝 모두 깊이 2를 사용하며, 비닝 효과와 입력 버퍼 효과를 혼동하지 않는다. 같은 픽셀의 두 이벤트는 head와 tail에 순서대로 보관하고, 타일 handshake마다 head 한 개만 제거한다.

CIFAR10-DVS 비교에서는 여섯 구조 모두 `EXTERNAL_RX_TIMESTAMP=1`을 사용한다. 모두 TIME 워드를 생략하고 수신기가 패킷 첫 헤더 워드의 도착 클록을 시각으로 기록한다. 무비닝 래퍼도 이 매개변수를 그대로 공유 core에 전달한다.

결합형도 같은 입력·FIFO·중재·선택기·16비트 링크를 사용한다. 차이는 이벤트가 정확히 하나인 타일을 `SPARSE` 한 워드로 보내고, 혼잡한 뱅크에서는 기존 손실형 뱅크 패킷을 선택한다는 점뿐이다. SPARSE와 BIN을 한 패킷에 섞기 위한 추가 마스크는 두지 않는다.

## 3. 형식 선택 차이

| 2×2 입력 | 적응형 | 무비닝 기준선 |
|---|---|---|
| 한 극성 네 픽셀 | BIN4 | RAW8 |
| 한 극성 세 픽셀 | GROUP3 | RAW8 |
| 두 픽셀 이하 | RAW8 | RAW8 |
| ON/OFF 혼합 | RAW8 | RAW8 |
| 같은 픽셀 ON/OFF 충돌 | RAW8+충돌 표시 | RAW8+충돌 표시 |

무비닝 기준선의 DATA는 항상 다음과 같다.

```text
[15:14] 00 = RAW8
[13:10] delta_t
[9:6]   ON[3:0]
[5:2]   OFF[3:0]
[1]     ON/OFF 충돌
[0]     예약
```

## 4. 현재 비교에서 주장할 수 있는 것

외부 수신 시각 모드에서 이벤트가 정확히 하나인 타일은 기존 행 RAW의 `HEADER+DATA` 두 워드 대신 `SPARSE` 한 워드를 사용한다. 이 절감은 위치와 극성을 모두 보존하므로 의도적 오차를 만들지 않는다. 반대로 3-of-4 손실형 BIN은 위치 하나를 버리므로 복원 오차에 포함한다.

패킹할 수 없는 입력에서는 적응형과 RAW8이 모두 유효 타일 하나를 16비트 DATA 워드 하나로 전송한다. 이 경우 출력 워드 수, 헤더와 타임스탬프 수, 패킷 길이가 동일하다.

같은 행에서 연속된 BIN4 타일 두 개가 선택되면 적응형 구조는 두 토큰을 한 DATA 워드에 넣지만 RAW8 기준선은 두 DATA 워드를 사용한다. 한 행의 네 타일이 모두 BIN4인 경우는 다음과 같다.

```text
적응형: HEADER 1 + TIME 1 + packed BIN4 2 = 4워드
RAW8:   HEADER 1 + TIME 1 + RAW8 4        = 6워드
```

16개 픽셀 이벤트 기준 이상적인 링크 처리량은 적응형이 `16/4 = 4 event/clk`, RAW8이 `16/6 ≈ 2.67 event/clk`다. 이는 파이프라인 채움과 입력 공백을 제외한 해당 패턴의 워드 수 비교이며, 모든 workload의 평균 처리량이나 PPA·최대 주파수 향상을 뜻하지 않는다. 형식 정확성, 위치 정보 보존, 실제 패킹 워드 수는 기능 시뮬레이션으로 주장할 수 있지만 PPA와 타이밍은 합성 및 배치·배선 결과로 별도 평가한다.

외부 수신 시각 모드의 행 융합은 다음과 같다.

```text
BIN4 동종 행:   HEADER 1 + ROW_BIN4 1
GROUP3 동종 행: HEADER 1 + ROW_GROUP3 1
혼합 행:        기존 타일별 DATA 경로
```

수신 시각은 융합 여부와 무관하게 헤더 첫 워드가 링크에 도착한 클록이다. 따라서 행 융합이 서로 다른 타일 발생 시각을 새 대표 시각으로 계산하지는 않는다. 다만 이 비교 모드 자체가 센서 발생 시각이 아니라 readout 시각을 사용하는 한계는 그대로 남는다.

외부 수신 시각 모드의 뱅크 융합은 다음과 같다.

```text
BANK_HEADER 1 + TILE_MASK 1 + PAYLOAD

RAW8:   PAYLOAD = ceil(유효 타일 수 / 2) 워드
GROUP3: PAYLOAD = ceil(유효 타일 수 × 3 / 16) 워드
BIN4:   PAYLOAD = 1워드
```

뱅크 패킷은 최대 10워드이므로 헤더 수신 시각과 마지막 데이터 도착 사이가 최대 9클록 벌어질 수 있다. 현재 규약에서는 뱅크 안의 모든 타일에 헤더 수신 시각을 기록한다. 100MHz에서는 최대 90ns, 200MHz에서는 최대 45ns의 패킷 내부 시간 뭉침이 생길 수 있으며, 센서 발생 시각을 보존하는 모드는 별도 연구가 필요하다.

## 5. 자동 검사 조건

`tb_aer_bank_fair_pair.v`는 BIN4와 GROUP3가 섞여 패킹되지 않는 동일 입력을 두 뱅크에 동시에 넣고 다음을 검사한다.

- `tile_in_ready`가 매 클록 동일
- pending 비트맵이 동일
- `out_valid`와 `out_last`가 동일
- HEADER와 TIME 워드가 동일
- 출력 워드 수가 동일
- DATA 워드에서만 허용된 형식 차이가 발생

`tb_aer_bank_packing_compare.v`는 한 행의 네 타일이 모두 BIN4인 동일 입력에서 적응형은 4워드, RAW8은 6워드를 출력하는지 검사한다.

`tb_aer_bank_row_fusion.v`는 외부 수신 시각 모드에서 BIN4 동종 행과 GROUP3 동종 행이 각각 `HEADER+DATA` 두 워드가 되는지, RAW8/GROUP3 혼합 행이 기존 타일별 형식으로 복귀하는지 검사한다.

`tb_aer_bank_fusion.v`는 16타일 BIN4가 3워드, GROUP3가 5워드, RAW8이 10워드로 전송되는지 검사한다. 또한 RAW8 타일 하나는 뱅크 패킷 3워드보다 기존 행 패킷 2워드가 작으므로 반드시 행 경로로 복귀하는지 확인한다.

`tb_aer_bank_lossy_mixed.v`는 3-of-4와 4-of-4가 같은 BIN으로 섞여 패킹되는 경우, 손실형 비용 이득이 없는 행 RAW 복귀, 손실형과 RAW 뱅크의 비용 동률에서 무손실 RAW를 선택하는 경우를 Python 기준 워드와 대조한다.

`tb_aer_bank_sparse_lossy.v`는 단일 이벤트가 한 워드 SPARSE로 출력되는지와, 같은 회로에서 혼잡한 RAW/BIN 혼합 뱅크가 기존 손실형 패킷과 동일한 다섯 워드로 출력되는지를 함께 검사한다.

`tb_aer_v1_raw_top_128.v`는 무비닝 128×128 전체 연결에서 `ON=1111`이 BIN4가 아니라 RAW8 `0x03C0`으로 출력되는지 확인한다.

`tb_aer_pixel_pending_array_depth2.v`는 같은 픽셀의 ON→OFF 순서, FIFO full 손실 계수, pop과 push의 동시 처리, 최종 drain을 검사한다.

2026년 8월 27일 로컬 Vivado 2024.1 XSim에서 SPARSE·손실형 혼합 패킷을 포함한 기능 회귀 15개와 128×128 CIFAR10-DVS 통합시험이 통과했다. 실행 스크립트는 출력 문자열의 `_FAIL`도 실패로 처리한다. 한 뱅크 논리합성 결과는 [AER SPARSE·손실형 비닝 결합 검증](AER_SPARSE_손실형_결합_검증.md)에 기록한다.

## 6. 앞으로의 유지 규칙

1. 계층, 버퍼, 중재, 타임스탬프 또는 패킷을 변경하면 공유 RTL에서 한 번만 수정한다.
2. 각 구조의 `ENABLE_BINNING`, `ENABLE_ROW_FUSION`, `ENABLE_BANK_FUSION`, `ENABLE_LOSSY_BINNING`, `ENABLE_SPARSE` 조합을 위 표대로 유지한다.
3. 모든 구조에 같은 입력을 넣고 주파수별 입력 파일 해시를 확인한다.
4. 비교 결과에는 공통 조건과 실제로 다른 RTL 매개변수를 함께 기록한다.
5. 처리량 결과에는 입력 패턴, 이벤트 수와 실제 출력 워드 수를 함께 기록한다. 패킹 가능한 패턴의 측정값을 모든 workload의 보편적인 처리량으로 확대하지 않는다.
6. 뱅크 패킷의 평균 지연뿐 아니라 패킷 잠금으로 악화될 수 있는 최대 지연도 함께 보고한다.
