# AER v1 공정 비교 규약

## 1. 비교 목적

픽셀 비닝의 효과만 분리해서 보기 위해 적응형 구조와 무비닝 RAW8 기준선이 같은 데이터 경로를 공유한다. 구조를 복사한 두 RTL을 따로 관리하지 않고 하나의 `ENABLE_BINNING` 매개변수만 다르게 설정한다.

```text
적응형: ENABLE_BINNING = 1
무비닝: ENABLE_BINNING = 0
```

무비닝은 이벤트를 픽셀별 개수로 축약하지 않는다는 뜻이다. 한 번에 읽은 2×2 타일의 `ON[3:0]`과 `OFF[3:0]`을 8비트 RAW 비트맵으로 그대로 보존한다.

## 2. 반드시 동일하게 유지할 조건

| 항목 | 공통 사양 |
|---|---|
| 센서 | 128×128픽셀 |
| 타일 입력 | 2×2, `ON[3:0]`, `OFF[3:0]`, `valid/ready` |
| 뱅크 | 4×4타일, 총 16×16뱅크 |
| 뱅크 선택 | 행 우선 순환, 빈 뱅크 건너뛰기 |
| 뱅크 내부 읽기 | 유효 행 선택 후 열 오름차순 |
| 대기 공간 | 타일당 토큰 한 개 |
| 시간 | 행 기준 16비트 시각과 타일별 4비트 시간차 |
| 출력 | 16비트, 동일 `valid/ready/last` |
| 입력 | 같은 이벤트와 같은 클록에 동시 인가 |

두 구조에서 달라도 되는 것은 타일 DATA 워드의 `format`과 `payload`뿐이다.

## 3. 형식 선택 차이

| 2×2 입력 | 적응형 | 무비닝 기준선 |
|---|---|---|
| 한 극성 네 픽셀 | BIN4 | RAW8 |
| 한 극성 세 픽셀 | GROUP3 | RAW8 |
| 두 픽셀 이하 | RAW8 | RAW8 |
| ON/OFF 혼합 | RAW8 | RAW8 |
| 같은 픽셀 ON/OFF 충돌 | RAW8+충돌 표시 | RAW8+충돌 표시 |

무비닝 기준선의 DATA는 항상 다음과 같다.

```text
[15:14] 00 = RAW8
[13:10] delta_t
[9:6]   ON[3:0]
[5:2]   OFF[3:0]
[1]     ON/OFF 충돌
[0]     예약
```

## 4. 현재 비교에서 주장할 수 있는 것

현재 적응형과 RAW8은 모두 유효 타일 하나를 16비트 DATA 워드 하나로 전송한다. 따라서 같은 타일 입력에서는 다음 값이 동일하다.

- 출력 워드 수
- 헤더와 타임스탬프 수
- 패킷 지연
- 링크 최대 처리량

현재 비교로 확인할 수 있는 것은 형식 선택의 정확성, 위치 정보 보존, DATA 비트 토글, 부호기 논리 차이다. `GROUP3/BIN4`가 선택된다는 사실만으로 링크 처리량이 증가한다고 주장하지 않는다.

실제 전송량 이득을 만들려면 적응형 형식의 짧아진 payload를 여러 개의 16비트 워드에 조밀하게 넣는 패킹 구조나 가변 폭 링크를 추가해야 한다. 이때도 RAW8 기준선과 센서·클록·FIFO 총비트·링크 폭·입력 추적을 동일하게 유지한다.

## 5. 자동 검사 조건

`tb_aer_bank_fair_pair.v`는 동일 입력을 두 뱅크에 동시에 넣고 다음을 검사한다.

- `tile_in_ready`가 매 클록 동일
- pending 비트맵이 동일
- `out_valid`와 `out_last`가 동일
- HEADER와 TIME 워드가 동일
- 출력 워드 수가 동일
- DATA 워드에서만 허용된 형식 차이가 발생

`tb_aer_v1_raw_top_128.v`는 무비닝 128×128 전체 연결에서 `ON=1111`이 BIN4가 아니라 RAW8 `0x03C0`으로 출력되는지 확인한다.

2026년 8월 20일 로컬 Vivado 2024.1 XSim에서 타일 짝 비교, 뱅크 짝 비교, 적응형 128×128 top, 무비닝 128×128 top을 포함한 v1 기능 시험이 모두 통과했다. 합성은 실행하지 않았다.

## 6. 앞으로의 유지 규칙

1. 계층, 버퍼, 중재, 타임스탬프 또는 패킷을 변경하면 공유 RTL에서 한 번만 수정한다.
2. 적응형 top은 `ENABLE_BINNING=1`, 무비닝 top은 `ENABLE_BINNING=0`을 유지한다.
3. 두 구조에 같은 입력을 넣는 짝 비교 시험을 항상 통과시킨다.
4. 비교 결과에는 공통 조건과 실제로 다른 RTL 매개변수를 함께 기록한다.
5. 고정 16비트 한 워드 구조가 유지되는 동안 비닝에 의한 링크 처리량 향상을 주장하지 않는다.
