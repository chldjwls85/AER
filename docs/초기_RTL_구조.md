# AER 초기 RTL 구조

## 1. 목적과 범위

이 문서는 AER-Compiler의 첫 번째 RTL 백엔드가 사용할 기준 구조를 정의한다. 처음부터 적응형 비닝과 여러 통신망을 모두 구현하지 않고, 비동기 픽셀 요청을 잃지 않고 저장한 뒤 계층형 중재를 거쳐 32비트 RAW 패킷으로 전달하는 경로를 먼저 검증한다.

초기 구현 범위는 다음과 같다.

- 16×16 픽셀 배열
- 4×4픽셀 타일 16개
- 2×2타일을 묶은 뱅크 4개
- 타일·뱅크·전역 단계의 순환 우선순위 중재
- 타일별 깊이 8의 동기 FIFO
- 32비트 RAW 패킷
- `ready/valid` 흐름 제어
- Verilog-2001 합성 가능 코드

아직 포함하지 않는 기능은 2×2/4×4 MASK, BIN, 혼잡 기반 형식 선택, SYNC 패킷, 메시 라우터 및 소프트웨어 복원이다.

## 2. 입력 규약

픽셀마다 `req_async`와 `polarity_async`를 입력받는다.

1. 픽셀은 이벤트가 발생하면 요청과 극성을 표시한다.
2. 픽셀은 해당 이벤트의 `ack`를 받을 때까지 요청과 극성을 유지한다.
3. RTL은 요청과 극성을 2단 플립플롭으로 동기화한다.
4. 동기화된 새 요청을 발견하면 극성과 8비트 시각을 픽셀별 저장부에 기록한다.
5. 이벤트가 타일 FIFO에 저장된 클록에 `ack`를 한 클록 동안 출력한다.
6. 요청이 다시 0으로 내려간 것을 확인한 뒤 해당 픽셀을 재무장한다.

따라서 클록보다 짧은 요청 펄스는 지원하지 않는다. 실제 센서 경계에서 요청을 유지할 수 없다면 별도의 비동기 래치 또는 핸드셰이크 회로가 필요하다.

픽셀 벡터는 행 우선 순서로 평탄화한다.

```text
pixel_index = y × 16 + x
```

## 3. 계층 구조

```text
aer_top
├─ aer_timebase
└─ aer_fabric
   ├─ aer_bank × 4
   │  ├─ aer_tile_raw × 4
   │  │  ├─ aer_event_capture × 16
   │  │  ├─ aer_rr_arbiter
   │  │  ├─ aer_raw_packetizer
   │  │  └─ aer_sync_fifo
   │  ├─ aer_rr_arbiter
   │  └─ aer_stream_reg
   ├─ aer_rr_arbiter
   └─ aer_stream_reg
```

각 뱅크는 8×8픽셀 영역을 담당한다.

```text
16×16 센서
├─ Bank 0: x=0..7,  y=0..7
├─ Bank 1: x=8..15, y=0..7
├─ Bank 2: x=0..7,  y=8..15
└─ Bank 3: x=8..15, y=8..15
```

타일과 뱅크 사이, 뱅크와 전역 출력 사이에는 `ready/valid` 인터페이스를 사용한다. 중재 포인터는 데이터가 실제로 다음 단계에 받아들여졌을 때만 이동한다. 뱅크와 전역 출력에 각각 한 단계의 탄력 레지스터를 두어 긴 조합 `ready` 경로를 줄인다.

## 4. 모듈 역할

| 모듈 | 역할 |
|---|---|
| `aer_event_capture` | 비동기 요청·극성 동기화, 이벤트 대기 상태와 시각 저장, ACK 생성 |
| `aer_timebase` | 전체 픽셀이 공유하는 8비트 순환 시각 생성 |
| `aer_rr_arbiter` | 마지막 전송 위치 다음부터 요청을 순환 탐색 |
| `aer_sync_fifo` | 타일이 만든 패킷을 저장하고 출력 정지에 대응 |
| `aer_stream_reg` | 1단 `ready/valid` 탄력 레지스터 |
| `aer_raw_packetizer` | 좌표·극성·시각을 32비트 RAW 패킷으로 구성 |
| `aer_tile_raw` | 4×4픽셀 저장부, 16:1 중재기, 패킷 생성기와 FIFO 결합 |
| `aer_bank` | 인접한 네 타일을 묶고 4:1 중재 수행 |
| `aer_fabric` | 네 뱅크를 묶고 전역 4:1 중재 수행 |
| `aer_top` | 행 우선 픽셀 벡터를 뱅크·타일 순서로 재배열하고 전체 구조 연결 |

## 5. RAW 패킷 v0

초기 패킷은 최대 1024×1024 센서 좌표를 담을 수 있도록 좌표마다 10비트를 고정 배정한다.

```text
31       30 29                 20 19                 10 9 8        1 0
+----------+---------------------+---------------------+-+----------+-+
| type=00  | x[9:0]              | y[9:0]              |p| time[7:0]|F|
+----------+---------------------+---------------------+-+----------+-+
```

- `type=00`: RAW 패킷
- `x`, `y`: 전역 센서 좌표
- `p`: ON/OFF 극성
- `time`: 동기화 경계에서 요청을 저장한 시각의 하위 8비트
- `F`: v0에서 0으로 고정한 예비 상태 비트

시각은 256클록마다 순환한다. 장시간 절대 시각과 순환 구분은 후속 SYNC 패킷에서 추가한다.

## 6. 이벤트 보존과 흐름 제어

픽셀 ACK는 외부 출력 완료가 아니라 타일 FIFO 저장 완료를 뜻한다. 출력이 막히면 다음 순서로 저장 공간을 사용한다.

```text
전역 출력 레지스터
← 뱅크 출력 레지스터
← 타일 FIFO
← 픽셀별 대기 저장부
```

타일 FIFO가 가득 차면 지역 중재기는 이벤트를 소비하지 않고 ACK도 보내지 않는다. 따라서 입력 규약을 만족하는 동안 과부하는 지연 증가로 나타나며, 임의의 이벤트 삭제로 나타나지 않는다.

## 7. AER-Compiler가 검증할 v0 제약

초기 수동 설정은 향후 컴파일러의 입력 검증 규칙이 된다.

- 센서 크기: 16×16
- 타일 크기: 4×4
- 뱅크당 타일: 2×2
- 패킷 폭: 32비트
- 좌표: 각 10비트, 센서 한 변 최대 1024
- FIFO 깊이: 8, 주소 폭 3
- 내부 리셋: 클록 동기식 active-low

후속 컴파일러는 센서 크기, 타일 크기, 뱅크 크기의 나누어떨어짐과 주소 폭, FIFO 주소 폭, 패킷 필드 합계를 RTL 생성 전에 검사해야 한다.

## 8. 자동 검사 조건

`tb_aer_rr_arbiter.v`는 순환 순서, 정지 중 선택 유지, 희소 요청과 무요청 동작을 검사한다. `tb_aer_top.v`는 다음 통합 조건을 검사한다.

- 단일 이벤트의 좌표와 극성이 정확히 한 번 출력됨
- 여러 타일과 뱅크의 동시 이벤트가 중복·누락되지 않음
- 256개 픽셀 동시 요청을 모두 처리함
- 출력 정지 중 패킷이 안정적으로 유지됨
- FIFO가 막히면 ACK를 보류하고 출력 재개 후 처리함
- 모든 시험이 끝난 뒤 예상 이벤트 수와 출력 이벤트 수가 같음

시험 환경은 출력 순서를 강제하지 않고, 좌표별 예상 이벤트 개수와 극성을 검사한다. 중재 순서의 개별 검증은 후속 중재기 단위 시험에서 확장한다.

### 현재 실행 결과

2026년 8월 18일 기준으로 다음 검사를 실행했다.

- Icarus Verilog 12.0, `-g2001 -Wall`: `AER_RR_ARBITER_PASS`
- Icarus Verilog 12.0, 통합 시험 289개 이벤트: `AER_RTL_PASS events=289`
- Yosys 0.52, `hierarchy -check; proc; opt; check`: `Found and reported 0 problems`
- Yosys 일반 셀 통계: 9,561개 셀, 16개 메모리, 총 4,096 메모리 비트

Yosys 셀 수는 기술 라이브러리에 매핑되지 않은 구조 진단값이다. 45nm 면적, 주파수와 전력 결과로 해석하면 안 되며, 이후 Genus 합성과 타이밍·전력 분석으로 별도 측정해야 한다.

## 9. 확장 순서

```text
M0 RAW 계층 통신
→ M1 2×2 MASK
→ M2 4×4 MASK와 BIN
→ M3 혼잡·패턴 기반 형식 선택
→ M4 AER-Compiler 후보 탐색과 RTL 생성
→ M5 메시·링·다중 출력 비교
```

`aer_tile_raw`의 출력 인터페이스를 유지한 채 후속 `aer_tile_adaptive`로 교체한다. 이렇게 하면 타일 내부 부호화와 상위 통신 계층을 독립적으로 비교할 수 있다.
