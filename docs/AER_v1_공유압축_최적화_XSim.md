# AER v1 영역 공유 압축 구조와 XSim 검증

## 1. 이번 변경의 범위

128×128 센서에서 기존에는 256개 뱅크마다 타일 분류기, 전송량 계산기,
RAW/BIN 선택기와 패킷 생성기를 각각 두었다. 이번 구조에서는 뱅크에는
손실 없는 RAW 스냅숏 저장부만 남기고, 4×4뱅크 영역마다 패킷 엔진 하나를
공유한다.

```text
128×128픽셀
→ 2×2픽셀 타일 4096개
→ 4×4타일 뱅크 256개: RAW 스냅숏만 저장
→ 4×4뱅크 영역 16개: 행 우선 순환 선택기 + 2엔트리 FIFO
→ 영역별 공유 패킷 엔진 16개
→ 전역 패킷 선택기
→ 16비트 출력 링크
```

압축 엔진 수는 256개에서 16개로 줄었다. 실제 면적 감소량은 아직 Genus로
측정하지 않았으므로 이 문서에서는 구조적 감소와 XSim 기능 결과만 보고한다.

## 2. V1 Baseline과 Proposed

V1의 대표 비교는 기존 행 단위 RAW 구조와 전체 Proposed 구조의 차이다.
외부 실험 조건은 같게 두되, 제안 기능인 뱅크 패킹을 Baseline에 넣지 않는다.

| 항목 | Baseline (`raw`) | Proposed (`sharedcare`) |
|---|---|---|
| 타일 입력 | 2×2 ON/OFF RAW 비트맵 | 동일 |
| 픽셀 FIFO | 깊이 2 | 동일 |
| 뱅크 선택 | 행 우선 순환, 빈 뱅크 건너뛰기 | 동일 원칙 |
| 전송 단위 | 유효 행의 타일을 RAW8로 개별 전송 | 뱅크 스냅숏을 묶어 전송 |
| 패킷 압축 | 없음 | SPARSE, BIN4, 선택적 GROUP3 |
| 압축 엔진 | 없음 | 4×4뱅크 영역마다 하나 공유 |
| 물리 링크 | 16비트 `valid/ready/last` | 동일 |

`sharedraw`는 Baseline이 아니다. Proposed의 스냅숏, 영역 FIFO와 뱅크 패킷
구조를 그대로 유지하고 압축 정책만 끈 절삭 실험용 구조다. 따라서
`sharedraw`와 `sharedcare`의 비교는 CARE 압축 정책의 순수 추가 효과를
확인할 때만 사용하고, V1의 대표 성능은 `raw`와 `sharedcare`로 비교한다.

## 3. 파이프라인과 저장 구조

공유 엔진의 판단 경로를 다음 네 구간으로 나눴다.

```text
스냅숏 캡처
→ 타일별 SPARSE/BIN4/GROUP3 분류
→ RAW와 압축 패킷의 실제 16비트 워드 수 비교
→ 네 타일 단위 순차 패킹 및 전송
```

각 뱅크는 형식별 데이터와 마스크를 중복 저장하지 않고, 타일당 RAW8 한
벌만 저장한다. 분류 결과는 선택된 뱅크가 공유 엔진에 들어온 뒤 생성한다.
영역 FIFO는 두 스냅숏을 저장해 엔진의 분류 또는 출력 역압 중에도 다음
뱅크를 받을 수 있게 한다.

타이밍 보고서에서 확인된 긴 조합 경로를 줄이기 위해 다음 세 부분도
수정했다.

- 16-way 순환 중재를 4개씩 묶은 계층 선택으로 바꾸고, 선택 결과를
  레지스터에 저장한 뒤 데이터 선택기로 전달한다.
- 2-entry FIFO가 가득 찼을 때 출력 `ready`가 입력 `ready`까지 같은
  사이클에 관통하지 않도록 했다.
- 뱅크 스냅숏을 소비하는 사이클에는 새 타일을 동시에 덮어쓰지 않고,
  다음 클록부터 다시 받도록 했다.

이 변경은 긴 중재·역압 경로를 레지스터에서 끊는 대신 서로 다른 패킷
사이에 1클록의 선택 시간을 추가한다. 추가 데이터 저장 레지스터는 넣지
않았다. 실제 최대 주파수와 면적 효과는 합성을 수행하지 않아 미확인이다.

## 4. 손실형 비닝 정책 수정

첫 구현은 압축 워드가 줄어들기만 하면 GROUP3를 사용했다. 8,000이벤트
시험에서 출력 워드는 줄었지만 3개 이벤트를 4개로 복원하면서 생긴 가짜
이벤트가 버퍼 드롭 감소량보다 많아 총 오류가 증가했다.

최종 정책은 다음과 같다.

- SPARSE와 4-of-4 BIN4는 정보 손실이 없으므로 비용이 작으면 사용한다.
- 3-of-4 GROUP3는 영역 FIFO가 혼잡할 때만 후보가 된다.
- 보통 혼잡에서는 가짜 이벤트 하나마다 최소 16비트 워드 하나를 줄이는
  경우에만 GROUP3를 허용한다.
- FIFO가 가득 차고 영역의 16개 뱅크가 모두 요청 중인 임계 혼잡에서는
  처리량 보호를 위해 GROUP3를 허용한다.
- 위 조건에서도 실제 직렬 워드 수가 RAW보다 작지 않으면 RAW로 돌아간다.

따라서 평상시에는 무손실 전송을 사용하고, 실제 지역 병목이 확인될 때만
공간 오차를 허용한다.

## 5. XSim 결과

공통 조건은 CIFAR10-DVS `airplane_0`, 시작 이벤트 0, 8,000이벤트,
1GEPS 입력, 픽셀 FIFO 깊이 2와 16비트 단일 링크다. 100MHz에서는 입력을
800클록, 200MHz에서는 1,600클록에 배치했다. 오류는 버퍼 드롭, 같은 사이클
중복과 GROUP3 복원 가짜 이벤트를 모두 포함한다.

### 100MHz: Baseline 대 Proposed

| 항목 | Baseline RAW | Proposed CARE | 변화 |
|---|---:|---:|---:|
| 수락 이벤트 | 7,271 | 7,323 | +52 |
| 드롭·중복 | 729 | 677 | -52 |
| 비닝 가짜 이벤트 | 0 | 23 | +23 |
| 전체 오류 | 729 (9.11%) | 700 (8.75%) | **29개, 3.98% 상대 감소** |
| 출력 워드 | 7,129 | 3,881 | **45.56% 감소** |
| 마지막 데이터 수신 사이클 | 9,466 | 4,943 | **47.78% 감소** |
| 패킷 무결성 오류 | 0 | 0 | 동일 |

Proposed가 입력 손실을 52개 줄였지만 GROUP3 복원으로 가짜 이벤트 23개가
추가돼 전체 오류의 순감소는 29개다.

### 200MHz: Baseline 대 Proposed

| 항목 | Baseline RAW | Proposed CARE | 변화 |
|---|---:|---:|---:|
| 수락 이벤트 | 7,295 | 7,425 | +130 |
| 드롭·중복 | 705 | 575 | -130 |
| 비닝 가짜 이벤트 | 0 | 39 | +39 |
| 전체 오류 | 705 (8.81%) | 614 (7.68%) | **91개, 12.91% 상대 감소** |
| 출력 워드 | 7,283 | 4,126 | **43.35% 감소** |
| 마지막 데이터 수신 사이클 | 9,712 | 5,342 | **45.00% 감소** |
| 패킷 무결성 오류 | 0 | 0 | 동일 |

Proposed가 입력 손실을 130개 줄였고 GROUP3 가짜 이벤트 39개를 포함한 뒤에도
전체 오류가 91개 감소했다.

### 절삭 실험 해석

`sharedraw`는 압축 정책의 순수 추가 효과를 확인하기 위한 절삭 실험이며
V1 Baseline이 아니다. 이번 타이밍 패치 뒤에는 `sharedraw`를 다시 측정하지
않았으므로 이전 절삭 수치를 현재 결과와 섞지 않는다. V1 대표 결과는 기존
행 단위 `raw` 대비 `sharedcare`의 100MHz 3.98%, 200MHz 12.91% 상대 오류
감소를 사용한다. 과거 추상 모델의 41.7%는 현재 RTL 성능 근거에서 제외한다.

## 6. 회귀시험

- XSim 기능 회귀시험 20개 통과
- Python 소프트웨어 시험 31개 통과
- 공유 엔진 SPARSE와 임계 혼잡 GROUP3 패킷 단위시험 통과
- RAW/CARE 공정 조건 시험 통과
- 뱅크 스냅숏 소비 뒤 다음 클록에 입력을 재수락하는 경계 시험 통과
- 다중 워드 패킷 중간에 `valid` 공백이 생겨도 grant가 바뀌지 않는 잠금 시험 통과
- 출력 역압 중 `data/valid/last` 안정성 시험 통과
- 실제 데이터 두 입력률에서 패킷 무결성 오류 0

재현 명령은 다음과 같다.

```powershell
.\scripts\run_v1_xsim.ps1
.\scripts\run_v1_cifar10_pending_xsim.ps1 -Mode raw        -PixelFifoDepth 2 -MaxEvents 8000 -StartEvent 0 -PlaybackSpeed 2255.5 -ClockHz 100000000 -Frames 0
.\scripts\run_v1_cifar10_pending_xsim.ps1 -Mode sharedcare -PixelFifoDepth 2 -MaxEvents 8000 -StartEvent 0 -PlaybackSpeed 2255.5 -ClockHz 100000000 -Frames 0
.\scripts\run_v1_cifar10_pending_xsim.ps1 -Mode raw        -PixelFifoDepth 2 -MaxEvents 8000 -StartEvent 0 -PlaybackSpeed 2255.5 -ClockHz 200000000 -Frames 0
.\scripts\run_v1_cifar10_pending_xsim.ps1 -Mode sharedcare -PixelFifoDepth 2 -MaxEvents 8000 -StartEvent 0 -PlaybackSpeed 2255.5 -ClockHz 200000000 -Frames 0
```

## 7. 아직 확인하지 않은 항목

이번 작업에서는 사용자의 기존 지시에 따라 합성을 실행하지 않았다. 따라서
다음 항목은 미확인이다.

- Genus 표준셀 면적
- 100MHz와 200MHz 타이밍 여유
- 동적·누설 전력
- 공유 스냅숏 선택기의 배선 및 fan-out 영향
- 배치배선 후 실제 주파수와 에너지/이벤트

다음 PPA 단계에서는 공정 RAW와 공유 CARE를 동일한 라이브러리, PVT, SDC,
입출력 부하와 활동률로 합성해야 한다.
