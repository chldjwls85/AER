# AER v1 영역 공유 압축 구조와 XSim 검증

## 1. 이번 변경의 범위

128×128 센서에서 기존에는 256개 뱅크마다 타일 분류기, 전송량 계산기,
RAW/BIN 선택기와 패킷 생성기를 각각 두었다. 이번 구조에서는 뱅크에는
손실 없는 RAW 스냅숏 저장부만 남기고, 4×4뱅크 영역마다 패킷 엔진 하나를
공유한다.

```text
128×128픽셀
→ 2×2픽셀 타일 4096개
→ 4×4타일 뱅크 256개: RAW 스냅숏만 저장
→ 4×4뱅크 영역 16개: 행 우선 순환 선택기 + 2엔트리 FIFO
→ 영역별 공유 패킷 엔진 16개
→ 전역 패킷 선택기
→ 16비트 출력 링크
```

압축 엔진 수는 256개에서 16개로 줄었다. 실제 면적 감소량은 아직 Genus로
측정하지 않았으므로 이 문서에서는 구조적 감소와 XSim 기능 결과만 보고한다.

## 2. 공정한 RAW 기준 구조

`aer_v1_raw_top_128`도 새 공유 구조를 사용한다. RAW와 CARE는 다음 조건이
같다.

- 픽셀 FIFO 깊이
- 뱅크별 16타일 RAW 스냅숏 저장부
- 영역별 행 우선 순환 뱅크 선택과 빈 뱅크 건너뛰기
- 2엔트리 영역 스냅숏 FIFO
- 스냅숏 캡처, 분류, 비용 계산, 전송의 파이프라인 단계
- 16비트 출력 링크와 `valid/ready/last` 역압
- 동일 입력 이벤트와 클록

차이는 공유 패킷 엔진의 선택 정책뿐이다. RAW는 손실 없는 RAW8 뱅크
패킷만 선택하고, CARE는 SPARSE, 손실 없는 BIN4, 혼잡 시 GROUP3를 선택할
수 있다.

## 3. 파이프라인과 저장 구조

공유 엔진의 판단 경로를 다음 네 구간으로 나눴다.

```text
스냅숏 캡처
→ 타일별 SPARSE/BIN4/GROUP3 분류
→ RAW와 압축 패킷의 실제 16비트 워드 수 비교
→ 네 타일 단위 순차 패킹 및 전송
```

각 뱅크는 형식별 데이터와 마스크를 중복 저장하지 않고, 타일당 RAW8 한
벌만 저장한다. 분류 결과는 선택된 뱅크가 공유 엔진에 들어온 뒤 생성한다.
영역 FIFO는 두 스냅숏을 저장해 엔진의 분류 또는 출력 역압 중에도 다음
뱅크를 받을 수 있게 한다.

## 4. 손실형 비닝 정책 수정

첫 구현은 압축 워드가 줄어들기만 하면 GROUP3를 사용했다. 8,000이벤트
시험에서 출력 워드는 줄었지만 3개 이벤트를 4개로 복원하면서 생긴 가짜
이벤트가 버퍼 드롭 감소량보다 많아 총 오류가 증가했다.

최종 정책은 다음과 같다.

- SPARSE와 4-of-4 BIN4는 정보 손실이 없으므로 비용이 작으면 사용한다.
- 3-of-4 GROUP3는 영역 FIFO가 혼잡할 때만 후보가 된다.
- 보통 혼잡에서는 가짜 이벤트 하나마다 최소 16비트 워드 하나를 줄이는
  경우에만 GROUP3를 허용한다.
- FIFO가 가득 차고 영역의 16개 뱅크가 모두 요청 중인 임계 혼잡에서는
  처리량 보호를 위해 GROUP3를 허용한다.
- 위 조건에서도 실제 직렬 워드 수가 RAW보다 작지 않으면 RAW로 돌아간다.

따라서 평상시에는 무손실 전송을 사용하고, 실제 지역 병목이 확인될 때만
공간 오차를 허용한다.

## 5. XSim 결과

공통 조건은 CIFAR10-DVS `airplane_0`, 시작 이벤트 0, 8,000이벤트,
픽셀 FIFO 깊이 2, 100MHz 모델이다. 오류는 버퍼 드롭, 같은 사이클 중복,
GROUP3 복원 가짜 이벤트를 모두 포함한다.

### 약 575Meps 입력

| 항목 | 공정 RAW | 공유 CARE | 변화 |
|---|---:|---:|---:|
| 수락 이벤트 | 7,422 | 7,463 | +41 |
| 드롭·중복 | 578 | 537 | -41 |
| 비닝 가짜 이벤트 | 0 | 33 | +33 |
| 전체 오류 | 578 | 570 | 1.38% 감소 |
| 출력 워드 | 4,661 | 4,239 | 9.05% 감소 |
| 마지막 데이터 수신 사이클 | 4,709 | 4,278 | 9.15% 감소 |
| 패킷 무결성 오류 | 0 | 0 | 동일 |

### 1Geps 입력

8,000이벤트를 800클록에 배치해 초당 10억 이벤트 입력 조건을 만들었다.

| 항목 | 공정 RAW | 공유 CARE | 변화 |
|---|---:|---:|---:|
| 수락 이벤트 | 7,320 | 7,375 | +55 |
| 드롭·중복 | 680 | 625 | -55 |
| 비닝 가짜 이벤트 | 0 | 48 | +48 |
| 전체 오류 | 680 | 673 | 1.03% 감소 |
| 출력 워드 | 4,357 | 4,006 | 8.06% 감소 |
| 마지막 데이터 수신 사이클 | 4,410 | 4,049 | 8.19% 감소 |
| 패킷 무결성 오류 | 0 | 0 | 동일 |

현재 데이터에서는 전송량과 배출 시간은 약 8~9% 줄었지만 전체 오류 감소는
약 1%다. 따라서 과거의 41.7% 오류 감소 수치를 이 구조의 결과로 사용하면
안 된다. 공정한 RTL 조건에서 확인된 값은 위 표가 기준이다.

## 6. 회귀시험

- XSim 기능 회귀시험 19개 통과
- Python 소프트웨어 시험 31개 통과
- 공유 엔진 SPARSE와 임계 혼잡 GROUP3 패킷 단위시험 통과
- RAW/CARE 공정 조건 시험 통과
- 뱅크 스냅숏의 소비와 같은 타일 새 이벤트 수락이 겹치는 경계 시험 통과
- 출력 역압 중 `data/valid/last` 안정성 시험 통과
- 실제 데이터 두 입력률에서 패킷 무결성 오류 0

재현 명령은 다음과 같다.

```powershell
.\scripts\run_v1_xsim.ps1
.\scripts\run_v1_cifar10_pending_xsim.ps1 -Mode sharedraw  -PixelFifoDepth 2
.\scripts\run_v1_cifar10_pending_xsim.ps1 -Mode sharedcare -PixelFifoDepth 2
```

## 7. 아직 확인하지 않은 항목

이번 작업에서는 사용자의 기존 지시에 따라 합성을 실행하지 않았다. 따라서
다음 항목은 미확인이다.

- Genus 표준셀 면적
- 100MHz와 200MHz 타이밍 여유
- 동적·누설 전력
- 공유 스냅숏 선택기의 배선 및 fan-out 영향
- 배치배선 후 실제 주파수와 에너지/이벤트

다음 PPA 단계에서는 공정 RAW와 공유 CARE를 동일한 라이브러리, PVT, SDC,
입출력 부하와 활동률로 합성해야 한다.
